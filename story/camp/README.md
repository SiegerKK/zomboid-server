# Сетап фермерского лагеря (PR #29)

Четыре скрипта `setup_phase01.sh` — `setup_phase04.sh` запускают по одному этапу через уже существующую команду `pz story build setup`. Они не создают и не запускают мир, не развёртывают моды и не обновляют сервер. **Без `--yes` выполняется только preview.**

**Репозиторий публичный.** Приватные `stages_build.json`, `phaseXX_items_batch.json`, `phaseXX_liquids_batch.json`, `phaseXX_bedding_batch.json` содержат координаты и инвентарь фермы, поэтому не коммитятся. Возьмите их из приватного пакета `farm_settlement_private_v9.zip` и храните вне Git, например в `/root/private-camp`. Можно поместить в `story/camp/private` — путь исключён через `.gitignore`.

## Предварительная проверка первого этапа

```bash
sudo bash story/camp/setup_phase01.sh camp_copy /root/private-camp
```

`camp_copy` — **заранее подготовленная копия** `story_test`. Копия должна содержать ту же карту и исходную ферму. Скрипты передают исходный мир `story_test` из приватного JSON; это не преобразование координат. Если файлы лежат в `story/camp/private`, второй аргумент можно опустить.

## Применение только после проверки копии

```bash
sudo bash story/camp/setup_phase01.sh camp_copy /root/private-camp \
  --survey /root/current-camp-copy.json \
  --backup /srv/zomboid/backups/worlds/camp_copy/world-EXISTING.tar.gz \
  --allow-existing --yes
```

Пути к AreaScan и холодному backup здесь условные: нужен **свежий полный скан** выбранного мира и реально существующий проверенный архив. Команда не создаёт backup. Требуются установленная совместимая версия `pz` и SiegerAdmin. Перед следующим этапом проверяйте появление объектов, реальные предметы и литры, сон, клиентскую синхронизацию и сохранение после рестарта. Отдельно запускайте `setup_phase02.sh`, затем III и IV.

## Контроль выполнения

```bash
sudo bash story/camp/setup_phase01.sh camp_copy /root/private-camp --status
```

Всё управление запросами, журналами и возобновлением (`--resume`) реализовано в `story/constructionsetup.py`. Обёртки фиксируют имя стадии и JSON-файлов и не допускают подмены аргументов `--file`, `--stage`, `--batch`, `--source-world`. Смотрите `docs/STORY_CAMP_SETUP_RU.md` по ограничениям, проверке точных квитанций и восстановлению после ошибок.

Ограничения: существующие планы не создают функциональные крыши, урожай, дождесборники, широкие автомобильные ворота и не гарантируют полные запасы на несколько недель. Подтверждение сервера не заменяет проверку в реальной Build 42.21.
