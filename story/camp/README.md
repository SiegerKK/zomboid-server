# Сцена фермерской базы `survival_farm`

Полный проверенный комплект входит в репозиторий:
[`scenes/survival_farm`](scenes/survival_farm). Владелец явно разрешил публикацию
этих планов и координат. ZIP, сырые сканы, сохранения, пользовательские базы и
секреты сюда не входят. Старые частные варианты можно оставить в `private/`,
который по-прежнему исключён из Git.

Сцена состоит из четырёх последовательных этапов. Она использует существующие
`pz story build setup`, нативное строительство и снабжение, без отдельного
сервиса или автоматического выполнения после обновления кода.

## Переработка сцен по игровым скриншотам — требуется новая приёмка

После первоначального игрового испытания сделана **новая редакция** сцен,
требующая повторной проверки в Build 42.21.0. В частности:

- Этапы I–II не складывают еду, воду, инструменты и оружие в удалённые
  северные сараи: активные запасы размещаются в доме и теплице.
  Продукты из старого северного набора перераспределены без изменения
  исходных количеств. Посуда, активные инструменты и личные записи
  расположены на проверяемых рабочих поверхностях; на земле остаются
  спальники и крупные садовые инструменты.
- К концу II этапа **только шесть окон первого этажа** укреплены снаружи
  по 1–2 доски. Все окна второго этажа открыты. В западной спальне
  `(9277,7783,1)` предусмотрен аварийный выход: две секции `SheetRope`,
  гвоздь и молоток доступны в комоде. Верёвка пока **не установлена**
  автоматически; окно, клетку под ним и фактический спуск надо проверить
  в клиенте Build 42.21. Стекло теплицы не заколачивается.
- Генератор II перенесён к бывшему куриному загону, рядом деревянный
  ящик `carpentry_01_16` с техническим ключом и канистрой Petrol,
  **не** с питьевой водой и консервами. Генератор выключен; электросеть
  ещё не проверена.
- Два новых жителя II спят в **спальниках**, без новой готовой мебели.
  На III этапе добавлена одна кровать у стены новой хижины, рядом один спальник.
  В казарме IV — одна кровать у стены и три спальника.
  Спальники поставляются как настоящие игровые предметы Camping, а не как
  нарисованные кровати; пригодность и размещение для сна проверяются игроком.
- Новые каркасы хижины и санблока на III этапе перенесены к северной
  мастерской, а новый южный оборонительный контур IV укорочен до Y=7787.
  **Новых объектов в низине Y>=7789 не планируется.** Высоты реального
  3D-рельефа исходный AreaScan не измеряет; это требует осмотра в клиенте.

**Это не та редакция**, которую предыдущий серверный отчёт принял как
315 строительных действий / 1102 предмета. Отчёт
[CAMP_STAGE_ACCEPTANCE_20261020_RU](../../docs/CAMP_STAGE_ACCEPTANCE_20261020_RU.md)
остается верной историей прошлой попытки. Текущие 4 этапа требуют **нового**
полного AreaScan, проверки native selector, вместимости контейнеров, двух
сторон баррикад и коллизий/ориентации кроватей на копии сохранения.
В текущем пересмотренном плане **286 строительных действий**
(2/6/73/205) и **1111 предметов** (137/197/308/469),
включая 2 верёвки и 1 гвоздь для аварийного выхода.
Старые нормы жидкостей не увеличены: 34 л Water + 20 л Petrol.
Пять новых рабочих и прикроватных столов добавлены на III–IV этапах.
Эти числа описывают *запросы*, не фактически выполненные действия.

Нельзя автоматически переиспользовать journal / native build ledger старых
сцен: изменены контрольные суммы фаз. Предыдущее применение нельзя
повторять с новым JSON ради «обновления» — нужен отдельный rollback по
согласованной контрольной точке и новое последовательное применение.
Обычный `git pull` ничего не меняет в игровых клетках.

## Выбрать любой подготовленный мир

```bash
sudo pz story build setup my_world --scene survival_farm --stage phase01
```

Это **preview**, без записи в мир. `my_world` — явное имя целевого слота;
поле `camp_template` в исходниках является идентификатором шаблона, не именем
слота, который надо создавать. Сцена не привязана к `story_test` и не меняет
исходные JSON при выборе назначения. На другом сервере нужен тот же
установленный репозиторий, совместимый `pz`, SiegerAdmin и Build 42.21.0.

Мир должен уже существовать, быть выбранным, запущенным и Story/Admin-ready.
Сцена не создаёт мир, не переключает его и не обновляет Workshop. Нужна та же
местность стандартной карты: координаты фиксированы, автоматически переносить
или поворачивать существующие здания/мебель нельзя. Изменённая карта,
переполненный контейнер, занятое место или незагруженные целевые клетки могут
заблокировать применение. «Любой мир» означает выбор назначения, а не обещание
слепого размещения на несовместимой карте.

## Применить ровно один этап

Сначала сохраните проверенный холодный backup целевого мира. Он не создаётся
командой setup. Затем войдите на ферму и получите свежий полный AreaScan
целевого мира, включающий оба этажа и весь периметр. Точная область сцены:
X=9255..9296, Y=7699..7799, Z=0..1. Например:

```bash
sudo pz story scan-area my_world --player EXACT_LOGIN --center 9275,7749 \
  --radius 50 --z-min 0 --z-max 1 \
  --include squares,objects,containers,items,ground,windows --yes
sudo pz story scan-status my_world
sudo pz story scan-report my_world --output /var/tmp/farm-before-01.json
sudo pz story build setup my_world --scene survival_farm --stage phase01 \
  --survey /var/tmp/farm-before-01.json
sudo pz story build setup my_world --scene survival_farm --stage phase01 \
  --survey /var/tmp/farm-before-01.json \
  --backup-name world-EXACT.tar.gz --allow-existing --yes
```

Замените логин и имя архива на реальные. Через ограниченный gateway указывайте
новое имя экспорта без каталога, используйте возвращённый абсолютный путь
`/var/lib/pz-codex/exports/...` как `--survey`. `--scene` не требует передачи
файлов из домашнего каталога; права broker не расширяются.

После выполнения получите **новый** снимок, затем проверьте:

```bash
sudo pz story build setup my_world --scene survival_farm --stage phase01 --status
sudo pz story build verify my_world --scene survival_farm --stage phase01 \
  --survey /var/tmp/farm-after-01.json
```

`QUEUED` — не подтверждение появления предметов. Требуются точные native ACK,
журнал setup, независимый скан предметов/жидкостей и оценка игрока. `verify`
проверяет конструкции, а не количество запасов. Только после своей оценки
повторите процедуру для `phase02`, затем `phase03`, затем `phase04`, каждый раз
со свежим снимком и отдельным явным подтверждением. Следующий этап не запускается
автоматически; зависимости проверяют строительство **и** снабжение предыдущего.

Повтор завершённого этапа с теми же исходниками возвращает `ALREADY APPLIED`.
Если выдача частична или результат неизвестен, не меняйте ID и не удаляйте
журнал ради повтора. `--resume` согласует известный запрос, а не повторяет
неподтверждённые изменения. `--retry-stock` разрешён только после доказанного
нулевого отказа preflight и не отключает проверку вместимости. Набор зависит от
свободного места; при другом содержимом существующих шкафов нужны отдельные
проверенные файлы раскладки. Сцена не очищает чужие предметы для освобождения места.

## Bash-обёртки и частные варианты

`setup_phase01.sh` — `setup_phase04.sh` по умолчанию берут этот встроенный набор:

```bash
sudo bash story/camp/setup_phase01.sh my_world
```

Необязательный второй аргумент или `PZ_CAMP_PLAN_DIR` выбирает другой каталог
планов. Исходная совместимость частных вариантов сохранена. Нельзя переопределять
фиксированные `--scene`, `--file`, `--stage`, `--batch`, `--source-world` через
оставшиеся аргументы обёртки.

## Хозяйственные записки (этапы II–IV)

В `story/scenes/` добавлены три отдельные сцены с десятью
читаемыми в игре документами: [II — быт и первый генератор](../../story/scenes/farm_household_02.json),
[III — мастерская, теплица, санитария](../../story/scenes/farm_household_03.json),
[IV — реестр жителей, склад, караул и резервное питание](../../story/scenes/farm_household_04.json).
На этапе I дополнительных записок нет. Все тексты написаны как рабочие
ведомости и инструкции самих жителей, без подсказок игроку.

**Встроенный `build setup --scene survival_farm` не добавляет эти
документы автоматически.** Они используют существующий `Story Director`
и могут быть применены **только отдельной подтверждённой live-сессией**
после осмотра соответствующего этапа и холодного бэкапа. Пока
исходные файлы записок привязаны к `story_test`, поэтому другие миры
их без отдельной адаптации не принимают. Координаты и поверхности
записок требуют свежего скана: теперь документы рассчитаны на **точные
столешницы с `support` и измеренной высотой**, по примеру сцены бара,
а не на голый пол. Индексы и свойства поверхности в игре должны совпасть.

См. [документальную схему и инструкции](../../docs/FARM_HOUSEHOLD_NOTES_RU.md).
Ни одна записка сама по себе не создаёт жильцов, работающий урожай
или запасы. Изменение документа не должно переписывать уже принятую
строительную стадию и её квитанцию.

Смысловая раскладка всех зон: [FARM_LEVEL_DESIGN_REVIEW_RU](../../docs/FARM_LEVEL_DESIGN_REVIEW_RU.md).

## Версия и границы

Первоначальная редакция действительно прошла серверную проверку
20.10.2026: 315 строительных действий, 1102 предмета и 54 л явно заданных
жидкостей — см. [исторический отчёт](../../docs/CAMP_STAGE_ACCEPTANCE_20261020_RU.md).
**Эта редакция изменена по замечаниям владельца и не принята сервером.**
Количества обычных предметов/жидкостей старой поставки сохранены,
добавлены только шесть спальников. Запросы и лимиты native API остаются
обязательными; сервер может отклонить новое распределение переполненных
ящиков. Мебель, внешний вид и новые площади северной застройки требуют
новой игровой проверки.

Правки опубликованного этапа меняют его контрольную сумму. Уже применённый
этап нельзя незаметно заменить новым содержимым: журнал откажет в повторе.
Для эволюции работающей базы нужны отдельные явно проверенные этапы/миграция,
а не изменение ID ради обхода защиты. Старые частные журналы с source world
`story_test` не усыновляются автоматически как `camp_template`.

Клиентская оценка всех дверей/кроватей/коллизий, проезд, два клиента и полная
сохранность базы после игрового рестарта отдельно не приняты. Каркасы не имеют
автоматических крыш, водопровода и электрической сети. Откат — отдельная явная
операция владельца; ни preview, ни setup не восстанавливают backup автоматически.
