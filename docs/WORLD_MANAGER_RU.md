# Управление несколькими мирами через pz

Подготовлен прототип единого менеджера (отдельный ZIP для пользователя). **НЕ установлен на VPS и НЕ протестирован на текущем игровом мире**. Установка требует проверки через Codex в окне обслуживания.

Желаемые команды: `pz start` (выбор мира по номеру, запуск Docker в фоне), `pz stop` (graceful shutdown), `pz save` (холодный backup + перезапуск после подтверждения), `pz save-live` (RCON save без остановки), `pz load` (restore в НОВЫЙ слот), `pz create NAME`, `pz list`, `pz status`, `pz logs`. Сохранения изолированы по каталогам `/srv/zomboid/worlds/<slot>/data`, но `SERVER_NAME=SiegerZomboid` должен оставаться неизменным внутри каждого слота.

Ветка Compose уже содержит `${PZ_WORLD_DATA_DIR:-/srv/zomboid/data}:/root/Zomboid`; **перед применением проверить наличие этого значения**. Импортировать `/srv/zomboid/data` **копированием**, без удаления оригинала; только после остановки игрового сервера и валидного backup. При смене слота Docker Compose должен пересоздавать контейнер с новым mount. Нельзя одновременно запускать ручные compose операции или старый backup script. Требуется единая блокировка и тест `save-live` RCON без утечки паролей.

Запрещено восстанавливать архив поверх действующего мира, переключать мир при запущенном сервере, удалять volumes через `down -v`. Работа в фоне — `up -d`; `PAUSE_EMPTY=true` ставит на паузу игровое время, **но не CPU/RAM контейнера**. Для полного выключения `pz stop`.

Перед production: test world A -> stop -> world B -> stop -> world A, отсутствие перекрёстных данных, SHA256 backup, restore to new slot, состояние игроков, rollback, перенесённый vanilla-мир. Отчёт о том, что реально выполнено, отдельно от того, что только в GitHub.
