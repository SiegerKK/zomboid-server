# Явное восстановление checkpoint в тот же слот

`pz story checkpoint-restore WORLD --file restore.json` проверяет архив и
показывает preview. Только `--yes` заменяет состояние выбранного остановленного
мира. Остановка и запуск — отдельные команды менеджера под общим lock.
Автоматического отката после сетапа нет. Требуется отдельное решение владельца.

Запрос (в приватном JSON вне Git):

```json
{"schema":1,"world":"my_world","archive":"world-EXACT.tar.gz","sha256":"EXACT_64_HEX_DIGEST"}
```

Имя архива берётся из `pz story backup-info --verify-latest my_world`,
контрольная сумма — из того же проверенного отчёта. Условные значения выше
не принимаются как действительные. Допускается только архив в
`/srv/zomboid/backups/worlds/WORLD/` с совпадающим sidecar SHA-256.

Обычный ограниченный `pz-vps` передаёт JSON через существующий broker:

```bash
pz-vps story checkpoint-restore my_world --file /home/codex-pz/restore.json
# В согласованное окно, players=0, штатная остановка:
pz-vps stop --yes
pz-vps story checkpoint-restore my_world --file /home/codex-pz/restore.json --yes
pz-vps start my_world
```

Новый root SSH, изменение sudoers, Docker group или произвольная shell-команда
для этого не нужны. Защищённый root-owned менеджер выполняет файловые операции
через уже установленный broker. Код сначала должен быть проверен и установлен.

Проверяются выбранный слот, чистая остановка Docker, точный mount `/root/Zomboid`,
имя мира, checksum, формат архива, снимок Mod IDs и доступное место на диске.
Пути с выходом из каталога, symlink/hardlink, устройства, sparse-файлы и
дублирующиеся имена отвергаются до замены слота. Действуют пределы распаковки:
64 GiB, миллион записей; превышение требует отдельного решения.

Архив сначала распаковывается в новый закрытый временный каталог; затем
**весь** существующий слот переносится в
`/srv/zomboid/checkpoint-preserved/WORLD-UNIQUE`. После этого подготовленный
каталог занимает прежний путь. При ошибке второго rename менеджер возвращает
старый каталог. Никакие текущие сохранения и исходные backup не удаляются.
Резервное место и каталог worlds должны находиться на одной файловой системе.

Восстанавливаются одновременно `data`, `story/setup`, live-журнал и нативный
ledger из `data/Lua`: квитанции после испытания не остаются доказательством
состояния до испытания. Другие миры, активное имя слота, Git, `.env`, Workshop,
музыка и настройки SSH не меняются. Старый каталог сохраняется до отдельной
команды владельца; автоматической очистки нет. Код не выполняет запуск игры.

Checkpoint создают при отсутствии незавершённых изменяющих запросов. После
восстановления нельзя переотправлять сохранённые команды старого испытания.
Отчёты о применении до восстановления не являются доказательством содержимого
восстановленного мира. Проверить запуск, состояние и новые сканы нужно отдельно.

Автотесты используют настоящие tar-архивы и временные каталоги, но моделируют
Docker. Реальное восстановление VPS и клиентская приёмка ещё не выполнены.
