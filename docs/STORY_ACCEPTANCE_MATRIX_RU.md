# Приёмка ВСЕХ команд PZ и Story Director на живом Build 42.21.0

**Статус:** план, не отчёт об уже проведённых проверках. Отметить `PASS` можно только с доказательством из настоящего мира или game/server лога. CI/заглушка Lua 5.1 — вспомогательное, не игровое доказательство. Для live-редактирования используется PR #8 в отдельном checkout; не менять `road_home` до явного согласия владельца.

## Правила работ

- Сверить `DEPLOYED_COMMIT`, `main`, ветку PR #8, `docker compose config`, хеш pinned image, `.env` root/0600 и действующие монтирования. Ничего не перезаписывать автоматически.
- Работа только в согласованное окно. Перед остановкой проверять **RCON players=0**. `sudo pz stop --yes` и `save --yes` сами по себе не заменяют эту проверку.
- Для игровых мутаций использовать `story_test` или новые восстановленные слоты; старый `road_home` лишь сохранить и проверить на неизменность. Не удалять никаких volumes/backup, не выполнять OS reboot и не менять SSH.
- Подтвердить SHA-256 холодных архивов и восстановление в **новый** слот. Одна тестовая копия для legacy `story apply` и отдельная для `apply-live`, чтобы результаты не перемешались. По итогам вернуть `road_home` в фон.
- Не мержить PR #8 пока `PASS` не имеют отправка/получение live действий, две игровые контрольные точки и поведение в двух клиентах.

## Результат для владельца

В `docs/STORY_ACCEPTANCE_REPORT_RU.md` заполнить таблицу результатов в формате:
`команда / слот / PASS|FAIL|SKIP / дата UTC / фактический лог или SHA / предостережение`.
`SKIP` допустим для опасных команд на production и ещё не реализованных функций — нельзя обозначать их как `PASS`. Для failed-проверок не скрывать подробности или отключать безопасность, а создать новый PR с исправлением.

Особые функции, **которых пока нет и не нужно изображать рабочими:** принудительный спавн именно TLOU-Clicker/Stalker, строение полноценных зданий, безопасный live-rollback отдельных предметов, live-бaррикады и инвентари игроков/автомобилей в сканере.
