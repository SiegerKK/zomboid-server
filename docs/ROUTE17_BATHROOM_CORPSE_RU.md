# Маршрут 17: сцена туалета Auto Shop (один труп + револьвер)

## Постановка

**Локация:** существующий Auto Shop, `story_test`; 1-й этаж `Z=0`.
**Сцена:** `story/scenes/smokeys_shop_04_bathroom_corpse.json`.
**Одно атомарное по управлению live-действие:** `bathroom_body_and_revolver`.
Создаётся один `IsoDeadBody` и один предмет `Base.Revolver` на той же
игровой клетке. Отдельного Lua-файла для каждой сцены нет: исполнение
осуществляет общий проверяемый серверный Story Director.

**Точные координаты:** `10602, 9403, 0` (room=`bathroom`).
**До установки, по снимку:** один пол
`floors_interior_tilesandwood_01_21` с `object_index=0` и мусор
`trash_01_36` (index 1), без стационарных унитаза/раковины на самой
целевой клетке. Шесть клеток нужного санузла:
`10601..10602, 9402..9404, Z=0`.
Соседние клетки: раковина 10601,9402; унитаз 10602,9402;
мусорная корзина с двумя tissue 10601,9404. Иной bathroom 10607,9384
не используется — это отдельный участок снимка.

Ожидаемая сцена: оставленное тело, револьвер рядом на полу и слабый
след крови (`blood=1`). **Причина смерти не подтверждается и не
приписывается пропавшей пятёрке**: игроки самостоятельно находят
обстоятельства. Не создаётся отдельный заражённый, не удаляются
существующие зомби, не нарушается общая сцена `smokeys_shop_03_infected`.

## Реализация и контроль

Новый тип действия `corpse`, только с заранее разрешёнными полями:
`room=bathroom`, точный `floor_sprite`, `blood=0..3`,
`ground_item=Base.Revolver`. Другие `room`, оружие и недоверенные
селекторы запрещены. Никакого произвольного Lua в запросе.
На game-server исполняется `createRandomDeadBody(square, blood)`,
написание возвращаемого `IsoDeadBody` проверяется в текущем `getDeadBodys`.
Старый труп на этой же клетке вызывает ошибку до каких-либо изменений.

Body и revolver помечаются в `modData`:
- `SiegerStoryQuest=smokeys_shop_04_bathroom_corpse`.
- `SiegerStoryAction=bathroom_body_and_revolver`.
- `SiegerStoryKind=corpse` / `item`.
- `SiegerStoryToken=SiegerStory:smokeys_shop_04_bathroom_corpse:bathroom_body_and_revolver:corpse`
  либо с суффиксом `:revolver`.

После создания обе сущности регистрируются как `spawn` в
`data/Lua/SiegerStoryQuestEvents.txt`; `pz story quest-status`
показывает отдельно `corpse_spawns` и `item_spawns`.
AreaScan показывает `kind=quest_corpse` у доступных помеченных тел
и `ground_item` с меткой у револьвера.
На трупы влияют механика разложения, переноска и удаление мира:
журнал — событие создания, не гарантия вечного существования объекта.

**Защита от дублирования:** на целевой квадрат перед первой операцией
ставится `:spawn_attempted`. После успеха — флаг `applied`.
Если процесс упал, запись не сохранилась или труп добавлен не полностью,
повтор будет заблокирован. Оператор проверяет мир/журнал вручную;
система не создаёт второй труп или револьвер автоматически.

## Что проверить до применения

1. Коммит/PR на GitHub принят для теста; CI/Python/Lua5.1 PASS.
2. В настоящем pinned B42.21.0 JVM провести offline/preflight smoke
   `createRandomDeadBody`, `IsoGridSquare.getDeadBodys`,
   сохранение `IsoDeadBody.getModData` и сетевую синхронизацию.
   **Доступность метода в JavaDocs не доказывает его поведение на
   выделенном сервере.**
3. Убедиться через RCON в `players=0`, сохранить текущее состояние,
   создать контрольный бэкап и перезапустить только игровой контейнер
   на `story_test` с обновлённым серверным runtime. Пользователь
   разрешил перезапуск, но не сброс и не замену мира.
4. Проверить, что после рестарта активный контейнер действительно
   загрузил новую версию `SiegerStoryDirector.lua`, обе игры/моды и RCON
   живы. Проверить `sudo pz story live-status story_test`. Нельзя
   начинать новую сессию при незавершённой или проваленной старой.
5. Сделать свежую **read-only** проверку целевой клетки:
   floor sprite, room, отсутствие уже созданного трупа/револьвера
   с новым токеном. Если мир изменился — остановиться, не создавать
   объект в случайной соседней комнате.

## Как применить

Оригинальный SHA-проверенный файл снимка должен существовать локально на VPS
(или передать путь к скану, присутствующему на машине).

```bash
# Read-only сверка всех shop-сцен, включая новый bathroom.
bash scripts/route17_autoshop.sh \
  --scan /var/tmp/workshop-survey-51x51x5-20261017-be026a6b.json \
  --scene smokeys_shop_04_bathroom_corpse

# Только после игрового smoke и обновления runtime, ровно одна сцена:
sudo bash scripts/route17_autoshop.sh \
  --scan /var/tmp/workshop-survey-51x51x5-20261017-be026a6b.json \
  --scene smokeys_shop_04_bathroom_corpse --apply --allow-corpses

sudo pz story live-status story_test
sudo pz story quest-status story_test smokeys_shop_04_bathroom_corpse
```

Если нет открытой live-сессии, согласовать `live-begin` с очередным
контрольным бэкапом при отсутствии игроков. Не выполнять `live-commit`
или новые сцены до фактического подтверждения результата.

## Критерии приёмки

- `live-status`: `bathroom_body_and_revolver=applied` (или `already`), без ошибок.
- `quest-status`: одна запись `corpse_spawns=1`, одна `item_spawns=1`,
  дубликатов нет.
- Игровой клиент действительно видит тело и револьвер **на одной клетке**;
  предмет можно поднять. Ни раковина, ни унитаз, ни проход не повреждены.
- На втором клиенте видны те же объекты. После сохранения и нормального
  перезапуска — корректная персистентность и отсутствие повторного спавна.
- Если `IsoDeadBody` не сохраняет метку при переноске/разложении,
  зафиксировать честное ограничение, не заявлять полноценный PASS.
- `road_home` и прочие миры не тронуты. Не восстанавливать
  `story_test` после тестов.

игроков люди покинули Smokey's, а в другой локации остались
следы случившегося. Этот труп — неизвестный, отдельная история.
