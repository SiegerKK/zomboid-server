# Проверка story_test без SiegerAdmin

Режим обратим и не активирует отложенную миграцию PR #31.
В отличие от минимального клиентского Admin, здесь Mod ID SiegerAdmin
полностью исключён из серверного MODS. Его Lua не должен загружаться.
Прежние файлы пакета остаются read-only для возможности возврата; наличие
каталога не означает включённый мод. Клиентский пакет менять не нужно,
но для проверки следует отключить SiegerAdmin и на клиенте.

Команды после остановки и свежей проверенной холодной копии:

```bash
sudo pz story admin-mode off story_test --yes
sudo pz start story_test
sudo pz story admin-mode status story_test
```

`on` выполняет обратное переключение с теми же gates. Никакого
восстановления мира, удаления предметов или автоматического отката нет.
Флаг относится только к story_test. Git update сам по себе Admin не отключает.
Существующие requests/receipts/scene guards сохраняются; перед повторным
включением нужно проверить ожидающие команды, особенно live-сцены.

## Ожидаемое разделение

| Функция | Без SiegerAdmin |
|---|---|
| Игра, TLOU/Forge, Viewpoint, Immersive Driving | Должны работать независимо |
| pz start/stop/save/load/list/status/logs и RCON save | Независимы от Admin |
| Docker CPU/RAM profile и engine-info | Независимы от Admin Lua |
| Нативная игровая роль admin | Не зависит от Mod ID SiegerAdmin |
| Серверный сканер животных | Остаётся в SiegerServer |
| NORTHBOUND и существующий клиентский SiegerRadio | Сохранены, требуется игровая проверка звука |
| Офлайн validate/preview и анализ сохранённых JSON | Не требуют игрового обработчика |
| Живые сканы объектов/зомби, запись поведения, Atlas | Обработчики выключены |
| Изменение времени, персонажа, инвентаря, машин | Административные обработчики выключены |
| Live-сцены, квестовые обработчики, стройка | Выключены; существующие объекты в save не удаляются |

Радио раньше зависело от глобального SiegerStoryScenes, создаваемого
Admin. Для эксперимента перенесён ТОЛЬКО ограниченный DATA-парсер приватного
bundle в доверенный standalone SiegerServerWorld.lua. Он загружается
после checksum через тот же ZombieBuddy callback, перед animal readiness,
проверяет мир и не регистрирует события/действия/строительство/персонажа.
Канонический источник — прежний ZZ_SiegerStoryScenes.lua; зеркало проверяется
генератором. Radio Lua и его checksum не изменяются. Это не скрытое включение
Story Director и не произвольный Lua/RCON eval.

CLI активных административных функций отказывает при off до постановки
новых запросов. Для радио требуется текущий server-ready с world_context=true
и точное совпадение mounts/радиокода. Исторические статусы и файлы не удаляются.
Сохранённые записки, мебель, машины и предметы используют штатные типы игры;
проверить их фактический вид нужно клиентом.

## Приёмка

Подготовлены тесты свежего backup/stop/world gates, переключения on/off,
отказа административного CLI и текущего независимого radio context.
Фактические результаты VPS будут записаны в PR после запуска. Не считать
слышимость радио, вход клиента или животный census подтверждёнными только
по CI/наличию файлов.
