## Клиент и API — PASS для ABI/автоматических тестов

Версия `sr17-v1-2dd38421ee0c`, runtime_revision=7. Клиент, серверный runtime,
станция и вложенный в полный клиентский ZIP каталог имеют одну версию.
Обновлённый серверный код пока **не развёрнут**. Установленный VPS по-прежнему
имеет f547aa6dd6f5: при разных handshake новая музыка будет отвергнута.
Перед игровой приёмкой требуется отдельное согласованное обновление серверного
кода и каталога; эта работа его не выполняет.

Сборка реального Java-моста выполнена JDK 25 против установленного game JAR,
SHA `e1a69eb743ede60b213a0fe7f8b83d4fcab773036d256cc4543a336f3b058a33`.
Reflection на реальном игровом JRE проверил восемь обязательных JNI методов и
`public static final native int FMOD_Channel_Set3DSpread(long,float)`.
В поставляемом JAR только siegerradio.bridge, никаких тестовых заглушек.

Начальный stereo Spread=120° — кандидат, не доказанный оптимум. Настоящие
FMOD_CREATESTREAM | FMOD_3D, физические X/Y/Z, near/far=4/12 сохранены.
Нет дополнительного музыкального потока, 2D-примеси, set3DLevel, изменений
глобального listener, окклюзии или громкости. Portable использует прежний 2D.
Отсутствующий/ошибающийся Spread даёт диагностический статус, сохраняя 3D.

Во время активного физического радио: ПКМ по миру →
`SiegerRadio: stereo 3D A/B` → 0/60/90/120 degrees. Меняется текущий канал,
без пересоздания/seek песни. В console.txt: SPREAD и SPATIAL; диагностика
не содержит координат или содержимого инвентарей. Прямые локальные функции:
`siegradioBridgeSetSpread`, `siegradioBridgeSpatialStatus`, `siegradioBridgeDetails`.

## Viewpoint — исследовано, исправление rear-mute ещё не принято

Read-only javap установленного Viewpoint.jar
(SHA `096bd37d63cb699ac95e9e7ea5245a1b9b5ff08c5161db35f6733b1d1c42b064`):
Patch_SoundListener → Hooks.soundListener → game.Hearing.listen.
При View.enabled основной listener получает forward/up из Look.yaw/pitch
или FreeCam и вызывает FMOD_Studio_Listener3D. Для обычного режима X/Y
берутся из игрового SoundListener, Z умножается на 3; freecam может менять
позицию listener. SoundLift отдельно корректирует штатные emitter-источники
для рельефа. Наш native stream не является FMODSoundEmitter; проверка иных
этажей/рельефа остаётся отдельным пунктом приёмки. Viewpoint не изменялся.

Это подтверждает поворот слушателя вместе с обзором, но не доказывает причину
провала уровня. Если Spread не помогает, сравнить Viewpoint ON/OFF и реальные
stereo/headphones vs surround настройки ОС/драйвера и игры. Ничего глобально
не переключать автоматически.

FMOD описывает Spread как распределение каналов многоканального сигнала
вокруг позиции источника: [официальный API](https://www.fmod.com/docs/2.02/api/core-api-channelcontrol.html#channelcontrol_set3dspread).

## Нагрузка

Полезный PCM-поток mono 44 100 B/s → stereo 88 200 B/s. Размер данных
удвоился; FMOD buffer size/CPU/RAM в игре здесь **не измерены**. Читается
короткий WAV-заголовок, музыка открывается CREATESTREAM по требованию.
Тесты проверяют освобождение при выключении, выходе из зоны, смене частоты
и завершении; возврат использует текущую позицию эфира, не начало трека.

Контрольный офлайн FFmpeg decode-to-null полного north_track_38, по 3 запуска:
median user+system CPU mono ~0.39 s, stereo ~0.57 s; RSS обоих ~51 MiB.
Это микротест FFmpeg (включая библиотеки/процесс), **не профиль FMOD**,
не величина игрового буфера и не прогноз FPS. Для игрового сравнения нужны
тот же участок трека/радио/позиция, одинаковые настройки и замеры клиента.
