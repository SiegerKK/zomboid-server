# Профиль персонажа: игровая приёмка НЕ ПРОЙДЕНА

**BLOCKED / не применять повторно:** на char16 сервер не находит выданные клиентом предметы, native equip не работает. См. [отчёт об инциденте](STORY_CHARACTER_INCIDENT_RU.md). ACK не означает корректный inventory pipeline.

`sudo pz story character apply story_test LOGIN --profile joel-arrival-v1` показывает preview.
Только `--yes` отправляет приватный запрос. Результат: `sudo pz story character status story_test`.
Нужен одинаковый клиент/сервер **radio-char16**, с включённым Lua checksum.

Профиль — наша ролевая интерпретация Джоэла первой трети TLoU, не каноническая таблица характеристик.
Сохраняет рубашку лесоруба, джинсы, носки, обувь, пояс, ID и связку ключей.
Остальной инвентарь (включая содержимое удалённых сумок) заменяется походным комплектом:
потёртые револьвер .357, дробовик, винтовка .308, нож, рюкзак, фонарь,
12/6/6 патронов соответственно, скромный запас еды, воды, лекарств и мелочей.
Оружие выдаётся незаряженным. Бутылка использует штатный factory FluidContainer;
уровень жидкости требуется проверить в игре, полный запас воды не предполагается.
Сила7, Fitness5, Aiming5, Reloading4, Blunt6, SmallBlunt5, SmallBlade5,
Sneak5, Lightfoot5, Nimble4, Woodwork4, Mechanics3, Doctor2.
Hunger=.18, Thirst=.12, Fatigue=.35, Stress=.30.
Две небольшие перевязанные экологические царапины: левое предплечье и правая голень.
Имеющиеся раны этих частей тела не перезаписываются: preflight отказывает.
Не меняет имя, профессию, черты, заражение, бессмертие, мир или другие персонажи.

Корневой CLI принимает только фиксированное имя профиля, без Lua/eval или произвольных payload.
Сервер сверяет активный story_test и точный логин, пишет guard перед отправкой,
не переотправляет после рестарта. Клиент проверяет все предметы, API и части тела до изменений,
помечает попытку в modData до первой записи. Ответ привязан к ID и игроку.
ACK означает только выполнение на клиенте. Двухклиентная репликация, сохранение после
перезахода и фактические health/XP требуют игровой приёмки. При частичной ошибке
автоматический повтор или rollback запрещён; файлы запроса архивировать только после аудита.

Профиль не применяется при обновлении, старте или подключении: нужна отдельная команда root.
Существующий batch исправлен для Stats:get/set(CharacterStat) Build42.21 вместо удалённых методов.

Боезапас и припасы складываются в надетый рюкзак; оружие и нож остаются в основном инвентаре.
В текущей ошибочной реализации изменения инвентаря выполняются только на клиенте.
Это не обеспечивает серверные item IDs и не проходит игровую приёмку;
`sendAddItemToContainer` / `sendRemoveItemFromContainer` не используются как мнимая синхронизация:
в реальном B42 JAR эти функции работают только на сервере. Сохранение инвентаря после выхода
и серверное обновление XP/здоровья проверяются отдельно, не предполагаются по ACK.

## Исправление по реальной игре
Первая попытка char14 дала Kick: AntiCheatPermission / ChangePlayerStats: no capability.
PlayerXp packet также требует CanModifyPlayerStatsInThePlayerStatsUI (проверено по аннотации реального JAR).
В char15 клиент НЕ вызывает SyncXp/sendPlayerStatsChange. PREPARE проверяет все действия без записей;
READY от точного целевого игрока позволяет серверу установить root-authorized baseline XP/Stats
и updateXpChecker, затем COMMIT изменяет клиент. Античит и права пользователя не меняются.
До новой выдачи после ошибки использовать `pz story character audit story_test LOGIN --profile joel-arrival-v1 --yes`.
Это read-only снимок навыков/показателей/двух царапин и marker, без изменения инвентаря.
Не повторять старый запрос: он мог частично/полностью выполниться до кика.

### Реальный Lua API: char16
В char15 серверная preflight остановилась на недоступном Lua `NetworkPlayerAI.updateXpChecker`;
она выполнялась до первого изменения baseline и до COMMIT клиенту. Проверка заранее нашла ошибку,
поэтому никакой автоматический повтор не выполняется. Исправлено через доступный глобальный
`addXpNoMultiplier(player, Perks.Strength, 0)` ПОСЛЕ установки точного baseline.
В настоящем JAR эта функция вызывает GameServer.addXp(player,perk,0,true), который
проверяет принадлежащего соединению игрока, вызывает AddXP с нулевым приращением и обновляет
xp-checker внутри Java. Нулевое приращение не даёт дополнительного опыта; множители не применяются.
Прямой доступ к NetworkPlayerAI из Lua, выдача capability и отключение античита не используются.
