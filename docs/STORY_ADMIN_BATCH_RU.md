# Онлайн-администрирование одним пакетом — PR #27

**Статус: Draft / только изменения кода.** Новый обработчик ещё не установлен
на работающий сервер. Он не загружает чанки и не изменяет что-либо при
запуске без запроса. Сначала нужна проверка на одноразовой копии мира,
включая двух клиентов и save/load.

## Уже существующее лечение

Прежняя команда `sudo pz story player-heal story_test LOGIN --experimental-health --yes`
уже вызывает `RestoreToFullHealth()` для частей тела. Однако реальная
синхронизация здоровья в B42 multiplayer ещё не доказана.

Новый интерфейс позволяет сделать это вместе с другими операциями,
одной серверной задачей:

```bash
sudo pz story batch preview road_home --file /root/story-edit.json
sudo pz story batch apply road_home --file /root/story-edit.json --yes
sudo pz story batch status road_home
```

Это работает для **точно выбранного активного** мира с установленным
Story runtime. Больше нет искусственного условия `world=story_test`,
списка из нескольких разрешённых предметов, максимума в пять предметов
или требования выгнать пассажиров из редактируемой машины.

## Пример /root/story-edit.json

Координаты, индексы объектов, названия предметов и прежние значения
ниже иллюстративные: перед применением их нужно заменить результатами
реального `scan-report`, `player-inspect` и `vehicle inspect`.

```json
{
  "schema": 1,
  "world": "road_home",
  "actions": [
    {
      "target": "vehicle",
      "id": 253,
      "script": "Base.PickUpTruck",
      "at": [10620, 9209, 0],
      "changes": [
        {"op": "condition", "part": "Engine", "expect": 65, "value": 100},
        {"op": "fuel", "expect": 8.5, "value": 32},
        {"op": "battery", "expect": 0.6, "value": 1},
        {"op": "add", "part": "TruckBed", "item": "Base.Plank", "count": 12},
        {"op": "remove", "part": "GloveBox", "item": "Base.Bandage", "count": 1}
      ]
    },
    {
      "target": "player",
      "username": "example_player",
      "changes": [
        {"op": "heal"},
        {"op": "stat", "name": "hunger", "value": 0},
        {"op": "add", "item": "Base.Bandage", "count": 5},
        {"op": "remove", "item": "Base.Plank", "count": 3}
      ]
    },
    {
      "target": "container",
      "at": [10622, 9210, 0],
      "source": "square",
      "object_index": 2,
      "container_index": 0,
      "container_type": "counter",
      "changes": [
        {"op": "add", "item": "Base.Bandage", "count": 2}
      ]
    },
    {
      "target": "ground",
      "at": [10621, 9210, 0],
      "changes": [
        {"op": "add", "item": "Base.Plank", "count": 2, "offset": [0.5, 0.5, 0]},
        {"op": "remove", "item": "Base.Bandage", "count": 1}
      ]
    }
  ]
}
```

`item` принимает любой реально установленный `Module.ItemName`,
включая модовые предметы. `container_type` и индексы должны совпасть
с точной загруженной квадратной/статической коллекцией; для ground
допускается адресное удаление по `world_index` с `count: 1`.
Дополнительный `stat` поддерживает `hunger/thirst/fatigue/stress`
со значениями в границах движка 0–1. Лечение восстанавливает части тела.

## Гарантии и пределы

- Только root CLI / приватные файлы `Lua/*.txt` / server-only обработчик.
  Нет RCON eval и команд от клиента. `preview` никогда ничего не отправляет.
- Предварительно проверяются **все** цели, значения `expect`, наличие API
  синхронизации, скрипты предметов и выбранные объекты/контейнеры.
  Любая такая ошибка отклоняет пакет до первой записи.
- До первой фактической записи фиксируется guard запроса. После частичного
  выполнения при ошибке ответ помечен `error` / `partial_possible`;
  автоматический повтор запрещён. Игровой мир не поддерживает атомарный
  откат сетевых изменений. `complete` означает серверное применение,
  **не доказательство репликации клиентам или сохранения на диск**.
- Число изменений ограничено только размером одного транспортного файла
  (до 4096 строк), количеством объектов и диапазонами API, а не тестовым
  whitelist. Большое количество предметов в одной команде всё равно может
  вызвать длинный игровой тик: предпочтительна подготовка вне нагрузки.
- Активный игрок для операций с телом/инвентарём должен быть онлайн.
  Машина/квадрат/контейнер должны быть уже загружены. Идентификаторы и
  координаты сверяются перед применением.
- Лечение, показатели персонажа и внешние контейнеры пока требуют
  реальной двухклиентной проверки и save/restart. Не использовать на
  единственной копии важного сохранения до такой приёмки.
- Поскольку `SiegerStoryBatch.lua` добавлен в public server Lua пакета
  SiegerRadio, развертывание требует согласованных серверного кода,
  клиентского ZIP/JAR и handshake **`radio-ops13`** с
  `DoLuaChecksum=true`. Без контролируемого обновления не включать.
