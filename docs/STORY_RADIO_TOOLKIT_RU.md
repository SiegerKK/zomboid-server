# SiegerRadio — инструмент сюжетных текстовых и звуковых передач

**Цель:** Project Zomboid **Build 42.21.0**, отдельный мир **story_test**,
не затрагивать `road_home`. Это набор инструментов и черновой MVP для теста,
**не утверждение о проверенной MP-передаче**. Никакой игровой мир, сейвы или
настройки модпака не изменяются одним Git-коммитом.

## Кратко: что действительно умеет MVP

1. **Текст на произвольной FM-частоте 88.0–108.0 МГц** с шагом 0.1 МГц.
   Сервер вызывает официальный `getZomboidRadio():SendTransmission(...)`,
   а **радиоприёмник игры**, не чат для всех, определяет, кто принимает текст.
2. **Клиентское аудио по ID:** сервер передаёт небольшую `SiegerRadio.CUE`
   команду, а предварительно установленный клиентский мод воспроизводит
   зарегистрированную запись. **Ни бинарные файлы, ни URL не отправляются**.
3. Режим `--scope tuned` в MVP слышен локальному игроку **только при
   включённом и заряженном переносном радио в основном инвентаре или руках,
   настроенном на точную частоту**. Встроенные автомобильные радиостанции,
   предметы в мешках/вложенных контейнерах и радиоприёмники на полу
   **пока не поддерживаются этим аудиофильтром**. Текстовая радио-система
   остаётся полноценной ванильной (включая совместимые устройства).
4. Режим `--scope global --allow-global` играет звук у всех подключённых
   игроков с установленным модом, независимо от радиоприёмников. Это **не
   игровая радиопередача**, а явный сюжетный аудиосигнал.
5. Это **не потоковое радио и не голосовой чат**. Сампл-точная синхронизация,
   продолжение в середине записи и локализация звука на конкретном радио
   без ZombieBuddy в MVP не обещаются. Воспроизведение начинается при
   получении сетевой команды с естественной небольшой задержкой.

## Архитектура и ограничения

- `story/radioctl.py` — root-owned Python CLI. Dry-run без `--yes`.
  Проверка `active-world`, Docker mounts, точной версии радио и
  глобальной частоты, ASCII/UTF-8 packet length, одного незавершённого
  запроса. **Нет RCON Lua eval и произвольного звукового имени**.
- `story/runtime/SiegerStoryRadio.lua` — новый необязательный серверный
  модуль, монтируемый только при включении Story для выбранного мира.
  Опрашивает ограниченный файл запроса раз в 120 тиков, без обхода мира.
  Для защиты от дублирования пишет `SiegerStoryRadioGuard.txt` до
  первой операции, затем `SiegerStoryRadioResult.txt` (ACK сервера).
- `mods/SiegerRadio/42/` — отдельный **клиентский** мод для аудио. Сервер
  не принимает команды «проиграй что хочешь» от клиента. Клиент может
  отправить только `HELLO` со версией/контрольной подписью каталога `sr17-v1-<hash>`.
- `story/radio/catalog.json` — разрешённые звуковые ID. Стартовый `test_tone`
  — короткий самостоятельно созданный тон без речи. Никаких
  чужих музыкальных файлов и стороннего Java-агента в комплекте нет.
- `scripts/radio_assets.py` — сборка каталога в клиентские и серверные
  allowlist + PZ sound definitions; новая запись требует распространения
  обновлённого клиентского пакета. **Сама передача текста и выбор уже
  установленного клипа не требуют изменений Git**.

**Безопасность:** если сервер ожидает аудио для нескольких игроков,
но хотя бы один подключённый клиент не подтвердил установку совместимого
мода, сервер отклонит аудио до отправки. Это предотвращает фиктивный
`COMPLETE` для отсутствующего клиентского мода; однако успешный серверный
ACK доказывает только отправку команды, а не реальное слышимое аудио.

Отправки разделены минимум **600 серверными тиками**. После неоднозначного
сбоя один и тот же запрос не повторяется автоматически. Новый запрос после
ошибки допускается только с `--acknowledge-failed` после ручной проверки.

## Команды для Codex (на будущей установленной сборке)

После установки новой серверной Lua runtime на `story_test`:

```bash
# Текстовое сообщение 101.3 МГц; без --yes = безопасный dry-run.
sudo pz story radio text story_test \
  --frequency 101.3 --source 10622,9221 \
  --signal-strength 100000 \
  --text 'NORTHBOUND, приём. Сохраняйте маршрутные книги.'

# То же с явным одобрением:
sudo pz story radio text story_test \
  --frequency 101.3 --source 10622,9221 \
  --text 'NORTHBOUND, приём. Сохраняйте маршрутные книги.' --yes

sudo pz story radio status story_test
```

Для звука нужно **сначала** установить клиентский мод всем игрокам:

```bash
# Просмотр готовых записей и совместимой версии клиента.
sudo pz story radio clips story_test

# Только те, у кого включена переносная рация на 101.3 МГц.
sudo pz story radio audio story_test \
  --frequency 101.3 --source 10622,9221 \
  --clip test_tone --scope tuned --allow-audio

# Применение — добавить --yes, затем проверить status.
sudo pz story radio audio story_test \
  --frequency 101.3 --source 10622,9221 \
  --clip test_tone --scope tuned --allow-audio --yes

# Сюжетный глобальный звук — отдельное повышенное разрешение:
sudo pz story radio audio story_test \
  --frequency 101.3 --source 10622,9221 \
  --clip test_tone --scope global --allow-audio --allow-global --yes
```

При `radio status` поле `clients_dispatched` — число **зарегистрированных
клиентов, для которых отправлена команда**, не число людей,
услышавших запись. `radio_api_called` в текстовом статусе означает
успех вызова штатного Java API, не подтверждение приёма устройствами.

Время начала: текущий момент получения сервером запроса. **Планировщик
по игровым часам и циклическая станция намеренно не включены в v1**:
сначала необходимо провести корректную MP-проверку передачи.

## Добавление своего голоса без ручного редактирования Lua

На рабочей машине с `ffmpeg`:

```bash
# Только предварительный просмотр.
python3 scripts/radio_assets.py add --clip helen_warning_01 \
  --source /var/tmp/helen_warning.ogg \
  --purpose 'Запись Хелен об эвакуации 7 ноября'

# Изменение каталога/мод-пакета и автоматическое обновление Lua:
python3 scripts/radio_assets.py add --clip helen_warning_01 \
  --source /var/tmp/helen_warning.ogg \
  --purpose 'Запись Хелен об эвакуации 7 ноября' --yes

python3 scripts/radio_assets.py check
```

Утилита преобразует источники OGG/WAV/MP3 в mono PCM 16-bit / 22 050 Hz,
ограничивает длину 0.1–60 секунд и размер 5 MiB. Регистрирует аудио
в `media/scripts/SiegerRadio_Sounds.txt` и в двух разрешённых Lua-каталогах,
не позволяет заменить существующий файл. Максимум 32 клипа.

**После добавления новых аудиофайлов** нужно собрать/раздать
версионированный клиентский мод (Workshop либо проверенная ручная установка)
и выполнить клиентский рестарт. Новые звуковые определения обычно не
подхватываются «на лету». Версия рукопожатия включает 12-символьный SHA-256 отпечаток
каталога клипов (включая хэши WAV). Генератор обновляет её одновременно
в серверном и клиентском Lua; старый клиент не пройдёт HELLO. Все исходные
WAV проверяются по SHA-256 перед сборкой. Инструмент не изменяет секреты или `config/mods.env`.

## Доставка клиентского мода

`mods/SiegerRadio/42/` содержит Build 42 `mod.info`, клиентский Lua,
регистрацию звука и тестовый WAV. Это **исходники мода, не автоматически
опубликованный Workshop-пакет**. Установка на отдельную машину:
перенести каталог `mods/SiegerRadio` в поддерживаемую игрой директорию
модов, включить `SiegerRadio`, затем проверить загрузку. В мультиплеере
нужно согласованно подключить его для сервера и клиентов через
проверенную систему распространения Workshop или инструкцию владельца.

Нельзя считать один server-side read-only bind `compose.story.yaml`
доставкой звуков клиентам. Не менять `road_home` и шесть активных TLOU-модов
без отдельного запроса. Конфликтующие Workshop радио-моды не ставить
в этот PR.

## Приёмочные проверки в настоящем Build 42.21.0 MP

1. CI + Lua 5.1/Python mock tests PASS; звуковой каталог и PCM тестовый
   файл валидны. Это **не** подтверждает реальное FMOD/радио на сервере.
2. При `RCON players=0`, выполнить cold checkpoint и согласованный
   рестарт только игрового контейнера `story_test`, не восстанавливая мир.
3. Установить клиентский мод двум тестовым игрокам на одинаковой версии,
   убедиться в HELLO/HELLO_ACK без ошибок `console.txt`.
4. На втором клиенте настроить включённую переносную рацию на 101.3 МГц;
   проверить текстовое сообщение. Без радио/на 101.4 МГц — не слышно
   и не видно радио-эфир по назначенной частоте.
5. Передать `test_tone` сначала `--scope tuned`: слышит только игрок
   с правильно настроенной рацией. Потом явно `--scope global`: слышат все.
6. Проверить два клиента, переподключение, ограничение повторов,
   отсутствие звука с неверной частотой, дубликата после рестарта,
   сохранение мира и радио-конфигурации.
7. При неуспехе остановить опыт; журнал/ACK и консольные ошибки сохранить
   приватно. Никаких переключений в `road_home`, сбросов и скрытых откатов.

`Custom Radio Station [B42]` с зависимостью ZombieBuddy. Это
