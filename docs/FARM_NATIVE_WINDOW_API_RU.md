# Исправление API окна перед обновлением PR #29

20.10.2026, проверка e2fa9194a243a62af99a83d0bba1954ee548ba4e.

В фактическом projectzomboid.jar Build 42.21.0 у IsoObject определён
`public void transmitModData()`. IsoWindow наследует этот метод.
Вызов `window:transmitModdata()` с маленькой d неверен: проверка API
отклонит новую баррикаду до её создания. Имя метода у IsoGridSquare
не является контрактом IsoWindow.

Исправлены проверка наличия и вызов на `transmitModData`, обновлено
checksum-идентичное зеркало SiegerAdmin и модель нативного окна в Lua-тесте.
Модель предоставляет только правильное имя: возврат ошибочного вызова
снова ломает положительные проверки строительства. Защита от чужих меток,
preflight и запрет повторного исполнения этапа сохранены.

Подтверждение: javap фактического игрового JAR; Lua 5.1 construction fixture,
Python construction/camp tests, admin_assets check. CI проверяется на новом
точном коммите перед установкой. Тестовые модели не доказывают сохранность
меток после настоящего игрового рестарта.

Это исправление влияет на новое строительство. Старые установленные доски
без меток на окнах автоматически не присваиваются и не переустанавливаются.
Обновление кода не повторяет сцены, не меняет их уже выданные предметы и
не восстанавливает checkpoint. После обновления клиентам нужен полный
SiegerAdmin из того же коммита при сохранённом DoLuaChecksum=true.
