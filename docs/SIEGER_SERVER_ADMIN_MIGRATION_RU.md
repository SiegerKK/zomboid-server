# Перенос серверной администрации в SiegerServer

Режим `admin-v1`, Build 42.21.0. Основа — проверенная ветка PR #30,
а не старый main. Реализация подготовлена; активация на VPS и игровая
приёмка этой миграции ещё НЕ выполнены.

## Что перенесено

Все 15 серверных Lua-модулей SiegerAdmin загружаются из `server/lua/admin`
через существующий lifecycle callback ZombieBuddy, после `finishChecksum`
и до настоящего `OnServerStarted`. Список закреплён в Bootstrap.java и
`server/admin-modules.json`; тесты проверяют соответствие.

- Story Director: обычные/live-сцены, записки, предметы, заражённые,
  трупы, окна, машины, журнал событий и защита от повторного исполнения.
- AreaScan, карта зданий Atlas, статистика и запись поведения зомби,
  диагностика TLOU/Forge и контроль фактического Sandbox.
- Управление временем, персонажами, предметами и машинами, пакетные
  операции, строительство и все этапы базы.
- Ограниченный парсер приватного bundle.txt.

Алгоритмы, имена файлов протокола, идентификаторы объектов, replay guards,
журналы и команды `pz` сохранены. Генератор копирует канонические
`story/runtime/*.lua`, добавляя только отметку успешной загрузки.
Старые модовые зеркала остаются для миров без миграции. Единственный
источник логики — прежние канонические runtime-файлы.

## Что остаётся на клиенте

Уменьшенный SiegerAdmin содержит ровно пять файлов: два mod.info,
SiegerStoryCharacterClient.lua, SiegerCharacterProfiles.lua и
SiegerInventoryIdentity.lua. Их содержимое идентично прежнему пакету.
Это обработчик подтверждения/сверки экипировки и его общие библиотеки.
Его удаление означало бы потерю надёжного восстановления инвентаря.

SiegerRadio и его музыка не меняются. После однократной чистой установки
уменьшенного SiegerAdmin изменения перенесённого серверного runtime не
меняют клиентский пакет. Изменения оставшегося клиентского протокола или
общих библиотек по-прежнему потребуют согласованного обновления клиентов.

## Однократная установка

Не распаковывать поверх старого SiegerAdmin: старые server/*.lua нужно
убрать из активной папки клиента целиком. Сохранить старую папку вне mods,
затем установить новый пакет. Не устанавливать уменьшенный пакет для
старого сервера до согласованного перехода: checksum-набор отличается.

```bash
python3 scripts/admin_assets.py check
python3 scripts/server_admin_assets.py check
python3 scripts/admin_pack.py --server-compat --output /PRIVATE/SiegerAdmin-SERVER-COMPAT-admin-v1.zip
```

После CI и согласования обслуживания, в root-owned checkout:

```bash
sudo pz stop --yes
sudo pz story server-admin enable story_test --client-ready --yes
sudo pz start story_test
sudo pz story server-admin status story_test
```

`enable` отказывает при работающем контейнере, другом мире, невалидных
assets или отсутствующем bundle; создаёт проверенную холодную копию до
атомарной записи маркера. Флаг `--client-ready` означает, что оператор
подготовил клиентский переход. Он не устанавливает клиентские файлы.

Опциональный `compose.server-admin.yaml` подключается последним и меняет
только источник mount SiegerAdmin на `server/client-compat/SiegerAdmin`,
добавляя PZ_SERVER_ADMIN=1. MODS/Workshop, радио, данные, UDP-порты и
лимиты памяти сохраняются. Простое обновление Git не включает миграцию.
Миры без собственного bundle и road_home не мигрируются.

Bootstrap отказывает при наличии старых административных обработчиков,
загружает каждый закреплённый путь один раз и проверяет отметки загрузки.
Частичная ошибка не создаёт admin-ready. CLI требует совпадение mounts,
мира и UUID текущего запуска. Готовность администрации записывается лишь
на реальном OnServerStarted, после регистрации обработчиков.
Ошибка bootstrap оставляет игру доступной для диагностики; это не означает
работоспособность администрации. Автоматического восстановления мира нет.

## Проверки

PASS локально:

- Полнота 15 модулей и соответствие канонической логике.
- Минимальный пакет: пять исходных файлов, без server Lua и музыки.
- Модель JVM: порядок загрузки, отсутствие двойной регистрации и изменений
  checksum, отказ выдавать ready при ошибке одного модуля.
- Compose: изменён только mount Admin; остальные mounts, MODS, порты,
  лимит памяти сохранены.
- Проверка свежего boot ID и отказ при неполных mounts/старом ready.
- LuaJIT 5.1: 17 поведенческих fixtures на перенесённых файлах — часы,
  зомби, Atlas, строительство, сканер, сцены/live/квесты/трупы/окна/машины,
  batch, ops, TLOU, player control и сверка инвентаря.
- Lifecycle harness: отказ от смешанного/повторного запуска, чужого
  bundle и преждевременного ready.
- Компилятор Kahlua из установленного игрового JAR: синтаксис 21 Lua-файла.
- Прежние тесты животных, Admin, Compose, live, сканера и часов.

Локальная оболочка Python 3.10 не поддерживает unittest.enterContext,
который используют прежние 29 тестов construction_setup. Эти тесты
проверяются CI на Python 3.12; исходные тесты под локальную версию не менялись.

BLOCKED до однократного перехода клиентов и согласованного запуска:

- Вход обычного игрока с DoLuaChecksum=true.
- Готовность новой администрации в настоящей серверной JVM.
- Скан и запись поведения возле игрока, live-сцена с идемпотентностью.
- Два клиента: отображение стройки/контейнеров/машины без перезахода.
- Сверка/выдача/экипировка с существующим клиентским обработчиком.
- Сохранение и обычный перезапуск без восстановления checkpoint.

Модельные тесты и компиляция не заменяют эту игровую приёмку. Миграция
не разрешает автоматически применять сцены или изменять персонажей.
