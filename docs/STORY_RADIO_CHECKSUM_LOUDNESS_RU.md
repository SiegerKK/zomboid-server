## Причина LuaChecksum

Совпадение номера радиопротокола НЕ доказывает совместимость LuaChecksum.
В Build42.21 LuaManager.LoadDirBase хэширует также серверные Lua, которые
на клиенте перечисляются без исполнения. Инъекция в ванильный media/lua/server
без аналогичного клиентского файла ломает перечень/порядок и общий checksum.
Администратор может иметь Capability.BypassLuaChecksum; вход администратора
не является приёмкой входа обычного игрока.

Канонический модуль станции перенесён из story/runtime в
`mods/SiegerRadio/42/media/lua/server/SiegerRadioStation.lua`.
Старое монтирование удалено, второй копии/loader-stub нет. В radio-overlay
вообще не остаётся монтирований в ванильное media/lua: Director, AreaScan,
PlayerControl, BarControl, Radio и RuntimeAudit входят в тот же клиентский
пакет; генератор проверяет их точное соответствие каноническим исходникам.
Серверная Java-декларация по-прежнему исключена отдельным mod.info, чтобы
ZombieBuddy не загружал клиентский мост на dedicated server.

Приватный bundle не отправляется клиентам и не превращается в клиентский
checksum-файл: он read-only монтируется как `Lua/SiegerStoryBundle.txt`.
Статический `ZZ_SiegerStoryScenes.lua` читает фиксированное имя и разбирает
ТОЛЬКО литералы генератора storyctl: таблицы, строки с decimal escapes,
целые числа, bool/nil. Ограничены размер4MiB и глубина20; код, вызовы функций
и хвост после данных запрещены. Нет loadstring/eval, обхода checksum или
патча движка. На клиентах loader сразу возвращается без чтения данных.
Имеющийся bundle.lua, сцены и сохранения не переписываются/не восстанавливаются.

Для radio-enabled story_test overlay сохраняет data/snapshot/agent/bootstrap
mounts, публикует только16261/16262 UDP. Остальные миры, включая road_home,
не переключаются на эту структуру. Legacy non-radio overlays сохраняют старые
инъекции и требуют отдельной миграции перед заявлением checksum-совместимости.

## Проверки и применение

PASS локально:32 применимых Python/Java/Lua checks, включая отказ от
исполняемого/повреждённого bundle, клиентский early return, точные world/code
mounts, отсутствие ванильных Lua mounts, один station runtime, проверку
генерируемых модулей. Реальная Kahlua из игрового JAR разбирает тестовые
данные; реальные JNI/libfmod подтверждают cabin60/exterior0 и priority32
при конкуренции голосов. Звук и ordinary-player login требуют клиента.

Тест test_tlou_source_contract.py требует аргумент snapshot и не является
самостоятельным CI-тестом без аргументов; пробный запуск без него дал IndexError.
Workshop для этого исправления не изменяется. Основной workflow включает
root smoke test и проверки Compose; результат свежего Actions смотреть в PR.

Перед развёртыванием: проверить RCON players=0, штатно сохранить/остановить
через pz. Установить проверенный Git commit, восстановить DoLuaChecksum=true
и AntiCheatChecksum=2 вместо временного bypass; запустить ТОТ ЖЕ story_test.
Проверить SHA внутри контейнера, mounts, loader/station startup и RCON.
Обоим клиентам установить полный новый ZIP при закрытой игре, затем проверить
вход обычными аккаунтами с включённым checksum и звучание в машине.
Нельзя объявлять обычный вход PASS только по совпадению SHA отдельных файлов.
