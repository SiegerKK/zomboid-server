## Найденные ошибки и исправления

1. Старые ID предметов отсутствовали в B42.21. Частные копии используют
реальные ID из установленной игры; количества сохранены.
2. Новые нативные баррикады смещают индексы существующей мебели.
Добавлен точный уникальный `object_sprite`, без поиска ближайшего объекта.
3. Некоторые исходные партии превышают настоящую вместимость.
Скан теперь измеряет нативную вместимость/свободное место/вес.
Партии распределены по проверенным существующим хранилищам и собственным
новым ящикам. Состав, количество, типы и объёмы жидкостей и наземные действия
сохранены. Нативная проверка вместимости не отключалась.
4. Для N и W стен исходный план использовал один западный спрайт.
Штатный B42 `entity_logwall.txt` задаёт W=`carpentry_02_80`, N=`carpentry_02_81`.
Ошибочная попытка остановилась после 5/73 стен, снабжение не запускалось.
План исправлен; новый preflight отвергает противоположную ось до первой записи.
Частично выполненный этап не повторялся и не объявлялся успешным.

Регрессионные проверки: Python construction 50, Lua 5.1 construction fixture,
тот же fixture в установленной Kahlua VM, канонические копии SiegerAdmin.
Полный CI точного коммита PASS:

## Команды фактического испытания

Для каждого этапа последовательно использовались следующие формы команд
с частными файлами вне Git и явно указанным холодным архивом:

```bash
pz story scan-area story_test --player admin --center X,Y --radius 50 \
  --z-min 0 --z-max 1 --include squares,objects,containers,items,ground,windows --yes
pz story scan-status story_test
pz story scan-report story_test --output UNIQUE.json
pz story build setup story_test --file PLAN.json --stage phaseNN \
  --batch ITEMS.json --batch LIQUIDS.json --batch BEDDING.json \
  --survey POST_PREVIOUS_STAGE.json --backup-name CHECKPOINT.tar.gz \
  --allow-existing --timeout 120 --yes
pz story build status story_test
pz story batch status story_test
pz story build verify story_test --file PLAN.json --stage phaseNN --survey POST_STAGE.json
```

У этапа I нет BEDDING.json. `X,Y`, `phaseNN` и пути здесь — обозначения,
не готовые команды размещения. Проверялись текущая серверная квитанция и
независимый JSON; вывод `QUEUED` сам по себе успешным применением не считался.
Все операции выполнялись через ограниченный `codex-pz` broker, без root SSH.

## Границы приёмки

PASS означает реальное создание и наблюдаемое снабжение на сервере.
Не подтверждены отдельно клиентские коллизии/проезд, взаимодействие со всеми
дверями и сон на всех кроватях, синхронизация с двумя клиентами и сохранность
полной базы после повторного игрового запуска. Каркасы не объявляются домами
с крышей, отоплением, водопроводом и электросетью. Генераторы первоначально
выключены, без топлива; их подключение не входит в это испытание.
Неизменяемые координаты плана нельзя автоматически переносить на другую карту:
универсальна команда и выбор мира, но нужен новый проверенный снимок назначения.

По исходному плану испытания полная база сохраняется холодным архивом,
после чего явно восстанавливается первоначальная контрольная точка этого же
слота. Точный итог восстановления и запуска фиксируется в отчёте PR.
Другие миры, Workshop, музыка и параметры SSH не изменяются. PR не объединён.
