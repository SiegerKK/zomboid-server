## Что мы можем отслеживать

При создании на каждом новом предмете и зомби сервер записывает в modData:

- `SiegerStoryToken` — индивидуальный токен `SiegerStory:clinic_quest_001:<action>:<ordinal>`.
- `SiegerStoryQuest` — `clinic_quest_001`.
- `SiegerStoryAction` — ID конкретного действия.
- `SiegerStoryKind` — `item` или `infected`.

Кроме модData записывается приватный **append-only** журнал
`<world>/data/Lua/SiegerStoryQuestEvents.txt`: события `spawn` для
предметов/врагов и `dead` для заражённых, когда срабатывает `OnZombieDead`.
Онлайн-ID зомби носит только диагностический характер; постоянная квестовая
идентичность — наш `SiegerStoryToken`.

Просмотр сводки:
```bash
sudo pz story quest-status story_test clinic_quest_001
sudo pz story quest-status story_test clinic_quest_001 --json
```

Новый сканер показывает `story_token`, `story_quest`, `story_action` на
предметах, пока они доступны скану, и `kind=quest_zombie` для **загруженных**
меченых зомби; это не полный поиск по всему миру.

**Ограничения:** предмет можно унести, израсходовать или уничтожить, а зомби —
переместиться, умереть/деспавниться вне загруженной области. Серверный журнал
считает созданные экземпляры и зафиксированные смерти; он **не доказывает**,
что оставшиеся экземпляры до сих пор существуют. Сохранность modData у
заражённых после выгрузки/перезапуска требует отдельной игровой проверки.
Никаких принудительных «возрождений потерявшихся» и очисток мира нет.

## Как развернуть и применить — инструкция Codex

1. Проверить актуальные PR #8 и PR #9 и зависимости. Текущий квест идёт
   отдельной веткой поверх PR #9, не на старом main. Не делать merge автоматически.
2. В root-owned checkout на VPS проверить
   `git status`, pinned Build 42.21.0, развёрнутый коммит, пути Docker mounts,
   сохранность TLOU/ZombieBuddy, `.env`, UDP и `story_test`. Сверить
   все действия JSON с **повторным локальным read-only сканом** существующих
   контейнеров. Если изменилась геометрия, selector, либо появились предметы —
   остановиться; не пытаться подобрать соседний шкаф вслепую.
3. Запустить CI, Python, Lua 5.1, pinned Java Kahlua и отдельный
   изолированный spawn-harness, проверить сигнатуру
   `addZombiesInOutfit(int,int,int,int,String,Integer)` и
   `IsoZombie:getModData()`, `Events.OnZombieDead` в pinned runtime.
4. Установка нового Lua требует согласованного перезапуска только игрового
   контейнера при RCON players=0, предварительно сделать валидный
   холодный бэкап. Не менять `road_home`, не перезагружать VPS.
   Не закрывать существующую live-сессию автоматически.
5. После запуска `story_test` и его готовности проверить:
```bash
sudo pz story live-status story_test
sudo pz story validate clinic_quest_001
sudo pz story preview clinic_quest_001
```
Если прежняя live-сессия открыта, использовать её. Если она **committed**,
запросить подтверждение нового `live-begin` при players=0 с новым cold
backup. Если сессия pending/failed, выяснить причину **до** нового квеста.
6. Запустить новый тестовый квест **только после доказательства адаптера
   спавна и повторной проверки всех пяти контейнеров**:
```bash
sudo pz story apply-live story_test clinic_quest_001 --allow-infected --yes
sudo pz story live-status story_test
sudo pz story quest-status story_test clinic_quest_001
```
Проверить все **11** action ID: 4 note, 1 loot, 6 infected.
`pending` означает, что клетка не загружена, не успех. При
`error` новый live-commit запрещён. Не повторять тот же action с новым
scene ID ради «исправления» — может создать дубли.

7. В игре проверить тексты всех 4 записок, 4 единицы награды,
   6 заспавненных зомби и их сетевую синхронизацию, повторный вход,
   сохранность меток. Два клиента нужны для утверждения MP PASS.
8. Сохранить игру с RCON save-live, сохранить текущие изменения мира,
   обновить приёмочный отчёт фактическими PASS/FAIL/BLOCKED.
   Завершающий `live-commit` с POST-холодным бэкапом только при нуле
   игроков и с согласия владельца. Восстанавливать мир **не нужно**.

**Важно:** само обновление Git не является применением квеста;
команда `apply-live` должна быть запущена явно. Не публиковать приватный
скан, журнал событий и координаты личных баз в публичный Git.
