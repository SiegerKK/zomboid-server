# Story Director: экспериментальное создание транспорта для Route 17

**Статус:** Draft/experimental. **Ни один автомобиль не создан на VPS**.
Этот PR зависит от чтения реальных автомобилей через AreaScan и от
выполнения Build 42.21.0 dedicated MP smoke. CI/Lua5.1 здесь не доказывают
физическую корректность, сохранение в world save и репликацию транспорта.

## Почему это отдельный инструмент

Для Smokey's по канону нужен белый фургон с предметами в бардачке.
У старого скана нет сведений об автомобилях, и мы **не знаем**, был ли
фургон уже припаркован, где находятся его реальные seat/trunk/glovebox
и не перекрыт ли въезд. Создавать новый фургон по умолчанию недопустимо:
это могло бы создать второй фургон рядом с уже существующим.

После установки PR #13 (vehicle scanner) необходимо:
1. В существующем мире `story_test` выполнить `pz story scan-player`
   возле Smokey's и Auto Shop при реально загруженной парковке.
2. Выгрузить JSON с `vehicle_snapshot=complete`, `vehicle`,
   `vehicle_part`, `vehicle_container`, `vehicle_item`.
3. По точному ID/скрипту/позиции найти нужный фургон; если он существует —
   **использовать этот экземпляр**, а не создавать дубль.
4. Отдельно проверить Lua API для установки канонических `H.'s Notes`
   в конкретный `GloveBox`, с защитой от дубликатов.
   Такой vehicle-inventory adapter здесь **ещё не реализован**.
5. Если фургон отсутствует, подобрать безопасную, подтверждённую
   машину и парковочную клетку из снимка. Только после этого создать
   review-only сцену отдельным PR и протестировать её.

## Новый опциональный тип сцены

```json
{
  "schema": 1,
  "id": "example_vehicle_route17_001",
  "world": "story_test",
  "title": "Example only — DO NOT APPLY",
  "enabled": false,
  "actions": [{
    "id": "reviewed_parked_van",
    "type": "vehicle",
    "enabled": false,
    "at": {"x": null, "y": null, "z": 0},
    "script": "Base.Van",
    "direction": "S",
    "skin_index": -1
  }]
}
```

Это **пример формата, не готовая сцена**: нет координат, нельзя
использовать `apply-live`. Публично доступные поля:
`script` только `Base.[A-Za-z0-9_]+`, `direction` только N/E/S/W,
`skin_index` -1..15, Z=0. Координаты ограничены двумя зонами Route 17:
Smokey's X10550..10680, Y9170..9280; Auto Shop X10550..10680,
Y9370..9440.

## Техническое исполнение

Только в существующей подтверждённой live-сессии `story_test`,
с явными флагами:

```bash
sudo pz story apply-live story_test REVIEWED_SCENE_ID --allow-vehicles --yes
```

Механизм:
- проверяет `ScriptManager.instance:getVehicle(script)` и
  `IsoDirections[direction]`; не принимает произвольный Lua код;
- проверяет `IsoGridSquare:isOutside()`, `isFree(false)` на
  сетке **5×7** загруженных клеток вокруг целевой точки;
- отклоняет любое текущее авто, центр которого ближе 8 клеток по
  каждой оси (правило консервативное, не полноценная collision solver);
- отклоняет персонажей ближе 10 клеток по осям; все проверки строго до
  первого изменения;
- перед созданием ставит в modData square `:spawn_attempted`,
  чтобы сбой не создавал бесконечные дубликаты;
- выполняет `addVehicleDebug(stockScript,IsoDirections.cardinal,skin,square)`;
- проверяет возвращённый `BaseVehicle`, script, назначает
  `SiegerStoryToken`, `SiegerStoryQuest`, `SiegerStoryAction`,
  `SiegerStoryKind=vehicle`;
- пишет приватное событие `spawn` с short vehicle ID в
  `SiegerStoryQuestEvents.txt`, выводит счётчик `vehicle_spawns`
  через `quest-status`.

Если внешний API создал машину, но вернул ошибку или журнал недоступен,
команда помечается FAILED и **автоматически не повторяется**. Разбор
неудачи — ручной, через AreaScan и логи. Скрипт никогда не уничтожает
существующие машины и не заменяет предметы в их контейнерах.

## Важные ограничения

- `addVehicleDebug` документирован как игровой Lua GlobalObject, но
  его безопасная и предсказуемая работа на нашем dedicated Build 42.21
  с TLOU/ZombieBuddy не подтверждена.
- Нужна реальная проверка на пустой парковке `story_test` с игроками
  вне радиуса 10 клеток: создание, физика, сетевое появление у двух
  клиентов, сохранение и повторный запуск **без восстановления мира**.
- Результат `vehicle_snapshot=complete` значит все **загруженные**
  машины в пределах скана, а не все машины по миру.
- После размещения машины отдельным этапом потребуется
  `vehicle_inventory` для `H.'s Notes`, фотографий и расходников.
- `road_home` и прочие миры не меняются; никакого reboot VPS,
  автоматического merge PR или установки на `story_test` отсюда нет.
