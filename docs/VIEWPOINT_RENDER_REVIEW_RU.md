# Viewpoint Lite: первая итерация клиентского код-аудита (Build 42.21)

Статус: **экспериментальный прототип, НЕ проверен на настоящем Viewpoint 0.1.6, НЕ готов для обязательной установки на multiplayer**.
Разработка только в отдельном PR; `main`, VPS, `story_test`, `road_home` и игровые сохранения не меняются.
Оригинальный `Viewpoint.jar` является закрытым продуктом; его код, шейдеры, JAR и пакеты текстур не включены в репозиторий.

## Что известно из публичных исходников и исследований

1. Viewpoint 0.1.5a Java: `FP.renderWorld → FP.snapshot → LootMenu.snapshot/show → InteractActions.update/gather` и вызов Lua `ViewpointInteract.harvest(player, object)`. В открытом техническом разборе независимого аддона отмечена **повторная сборка меню на каждом кадре**. Это разумная гипотеза для снижения небольших CPU/Lua-аллокаций. На версии Viewpoint **0.1.6** API и стоимость необходимо подтвердить заново: https://github.com/NathanC8450/viewpoint-fixes/blob/main/docs/viewpoint.md .
2. Viewpoint Turbo уже использовал кэш **повторных shader uniforms** и пакеты аллокации **floor texture array 8 вместо 32 слоёв** для 0.1.5a. Автор и пользователи сообщили, что на 0.1.6 старый патч отключается по несовпадению JAR; отключение защиты по хэшу — НЕ решение: https://steamcommunity.com/sharedfiles/filedetails/?id=3812559973 .
3. В реальном журнале Viewpoint одного из пользователей: **337/384 МиБ floor pages, 279/512 МиБ model packs**, ~11.6 ГиБ *process committed* при 2.3 ГиБ Java heap. Это **не метрика нашего друга и не доказательство утечки**. С iGPU выделения GL делят физическую RAM с Windows, поэтому возможен memory pressure: https://steamcommunity.com/workshop/filedetails/discussion/3809306528/586188069723648503/ .
4. На AMD Radeon Vega iGPU с Viewpoint 0.1.6 есть отчёт о GLSL-ошибке `variable indexing sampler array` в семи шейдерах. Это потенциальный дефект совместимости драйвера/GLSL, не доказанная ошибка выделения памяти: https://theindiestone.com/forums/topic/102407-viewpoint-016-the-renderer-could-not-start-on-amd-radeon-vega-igpu-7-shaders-fail-with-variable-indexing-sampler-array/ .
5. В одном старом независимом профиле Viewpoint 0.1.5a в 3D была GPU-bound нагрузка и существенный рост Java heap при езде, но это стенд с мощной дискретной GPU, не репрезентативный тест на 8 ГБ: https://github.com/xD3I/PZ_Optimization/blob/master/docs/findings-viewpoint-2026-10-07.md .

## Что конкретно сделано сейчас

**`SiegerViewpointLite`** — небольшой отдельный клиентский **Lua-only** мод. Его можно выключить одним чекбоксом `Options → Mods → Viewpoint Lite → Reduce duplicate Viewpoint interaction menu builds` (по умолчанию **OFF**).

Когда пользователь *явно* разрешит экспериментальную оптимизацию, обёртка `ViewpointInteract.harvest` повторно использует **две связанные величины**: исходную таблицу результата `{title, labels, enabled, seen}` и опубликованную таблицу `ViewpointInteract.actions`, максимум **50 миллисекунд** и только для того же `player + target`. Возврат `nil`, ошибка/диагностика `{why=...}` или результат без `labels/enabled` **не кэшируется**. Это исправление ошибки раннего прототипа, в котором тест возвращал `nil` вместо реального результата и потому не выявлял несовместимость. Реальное состояние живого меню всё равно может измениться в течение 50 мс — требуется игровая проверка. Кэш автоматически сбрасывается при:
- смене игрока или целевого объекта;
- выполнении действия `ViewpointInteract.run`;
- замене таблицы действий третьим модом (изменения содержимого той же таблицы отдельно не отслеживаются);
- истечении 50 мс, смене времени на более раннее, уходе в главное меню;
- выключенном чекбоксе;
- наличии известного `ViewpointFixes` или `ViewpointPlacementFix` (во избежание обхода взаимодействий этих модов);
- отсутствии нужных Viewpoint Lua API/времени.

**Нет** Java/JNI, OpenGL-перехватов, кэша между мирами, читов, передачи координат или влияния на симуляцию. Потребление памяти кэшем — ссылки на один текущий список/игрока/объект максимум 50 мс; не создаются копии.

Результат ограничен: **это снижение потенциальных CPU/Lua/GC накладных расходов в меню, а не оптимизация GL/VRAM, и не обещание заметного выигрыша на 8 ГБ iGPU**. При любом баге взаимодействий немедленно отключить чекбокс/мод. Не заставлять всех игроков устанавливать экспериментальный мод.

## Инструмент для настоящего аудита Viewpoint.jar

`scripts/viewpoint_jar_audit.py` — только чтение. Пользователь запускает ЛОКАЛЬНО на законно установленном JAR:

```bash
python3 scripts/viewpoint_jar_audit.py "/path/to/Viewpoint.jar"
# Для точно известной версии можно дополнительно включить:
python3 scripts/viewpoint_jar_audit.py "/path/to/Viewpoint.jar" --expect-sha256 <полные 64 символа>
```

Инструмент печатает SHA-256 и **Java constant-pool method references** классов `viewpoint.*` к вызовам GL создания/освобождения текстур, массивов, буферов, FBO и shader-uniforms. Он не загружает классы, не выполняет Viewpoint, не декомпилирует и не извлекает байткод/GLSL. Никакие пользовательские файлы не изменяются.

**Границы анализа:** наличие ссылки на `glGenTextures` без ссылки на `glDeleteTextures` в том же классе НЕ означает утечку — очистка может быть в другом классе. Наличие ссылки на uniform-вызов НЕ означает, что он выполняется каждый кадр. Для выводов о дефекте нужны точный JAR, bytecode call graph, runtime GL resource counts/VRAM и трасса dispose.

## Сборка независимого ZIP из исходников (локальный эксперимент)

Сборка не требует игрового JAR или аудиофайлов и намеренно пакует ровно
два файла: `42/mod.info` и `42/media/lua/client/SiegerViewpointLite.lua`.

```bash
python3 scripts/viewpoint_lite_pack.py build --output /tmp/SiegerViewpointLite-EXPERIMENTAL.zip
python3 scripts/viewpoint_lite_pack.py verify /tmp/SiegerViewpointLite-EXPERIMENTAL.zip
```

CI публикует ZIP и SHA256 в артефакте `viewpoint-lite-experimental` (draft-only).
На Windows после полного закрытия игры распаковать папку `SiegerViewpointLite`
в `%USERPROFILE%\Zomboid\mods`. Внутри игры выбрать мод для **тестового одиночного мира**,
открыть `Options → Mods → Viewpoint Lite` и явно включить флаг (OFF по умолчанию).
Чтобы откатить — выключить флаг либо мод; файлы Viewpoint не меняются.

**Не включать на серверной MP-сессии до проверки LuaChecksum и разрешённого
состава модов.** ZIP в GitHub Actions не подтверждает совместимость с
закрытым Viewpoint 0.1.6.

## Приоритеты настоящего Java GPU-патча (ПОКА НЕ РЕАЛИЗОВАНЫ)

1. **P1**: проверить `floor pages` и модельные кэши: страницы, capacity, retry-рост, возврат ресурсов и GL context reload. Сравнить реальный 0.1.6 JAR и число OpenGL аллокаций при повторном посещении той же области. Не устанавливать фиксированный меньший batch вслепую: он может увеличить число GL draw calls и ухудшить FPS.
2. **P2**: в shader uniform cache ключом должен быть **program ID + uniform location + тип/значение**, с инвалидированием на `glLinkProgram`, смену контекста и перезапуск shaderpack. Наивный кэш по location ломает разные программы.
3. **P3**: проверить persistent buffer ring/FBO lifecycle и правильный `glDelete*` в случае exception, загрузки нового мира, выключения Viewpoint, смены разрешения и hot shader reload.
4. **P4**: поддержка AMD/Intel GLSL с корректной версией и constant-index sampler array только после точного просмотра кода соответствующих семи шейдеров.

## Проверки и эксплуатационные границы

CI проводит `luac5.1` + Lua mock, моделирующий реальный контракт результата-таблицы (а не `nil`), для **OFF по умолчанию**, совпадения возвращаемой таблицы при cache hit, обхода для `nil`/`{why=...}`, разных игроков/целей, сброса при действии, просрочке и при наличии других модов. Python-тест использует искусственный JAR и подтверждает read-only анализ и SHA-pin. **Ни один из них не проверяет живой Viewpoint 0.1.6**.

На компьютере друга для теста нужно:
1. Сначала одиночный мир, закрытая игра перед заменой модов; не активировать на боевом MP до проверки checksum и согласования состава модов.
2. С Viewpoint и без других совместимых хуков измерить 1–2 минуты в одинаковом месте, сначала checkbox OFF, затем ON. Профиль Viewpoint и мод-пак остаются неизменными.
3. Проверить целеуказание, доступность контекстных действий, подбор, взаимодействие с автомобилем и смену объектов; при малейшем рассогласовании отключить.
4. Сравнить `Viewpoint` GPU passes, `main thread`, GC и системную RAM. Не измерять «память спасена» на основании одного FPS.
5. Для отдельного GPU-патча нужен локальный Viewpoint 0.1.6 JAR или JSON от read-only аудитора; пока нет соответствующего проверенного JAR, bytecode patch **не собирать**.

Полезный немедленный тест без патча: включить **Texture Compression** в штатных настройках Project Zomboid — для одного AMD-инцидента это сняло экстремальные 3–5 FPS. На iGPU с 8 ГБ RAM также важно отключить лишние 3D-модельные пакеты; не увеличивать `-Xmx` до 8 ГБ. См. обсуждение: https://steamcommunity.com/workshop/filedetails/discussion/3809306528/586188069723648503/ .

**Не изменять настройки пользователей на сервере, не ослаблять DoLuaChecksum, не менять исходники Viewpoint и не копировать в Git приватный JAR.**
