# SiegerRadio: потоковое аудио по требованию — PR #24

## Статус и границы проверки

Клиентское Java-расширение и Lua-интеграция написаны; Java/JVM-mock и Lua
регрессионные сценарии в CI проверяют seek, 2D/3D, stop/release, неверные
файлы, позднее подключение, выключение/возвращение, отключение питания.
**Реальный JavaFMOD ABI и слышимый звук на pinned PZ Build 42.21.0
двумя игроками пока не подтверждены.** При несовместимости расширение
отказывает в запуске, не переводит радио на старую постоянную «немую»
загрузку. Не объявлять эту функцию прошедшей игровую приёмку по одному CI.

## Архитектура

Сервер не открывает аудиофайлы. Он знает clip ID, durationMs и оставшееся
время текущей песни, рассылает только короткий STATION_TRACK на **101.2**.
Клиент хранит это состояние в Lua, не запускает звук, пока отсутствует
доступный включённый приёмник. После включения/подхода Lua рассчитывает
offsetMs = durationMs - remainingMs + elapsedOnClientMs.

**Только клиентский** ZombieBuddy Java JAR из
`mods/SiegerRadio/42/media/java/client/SiegerRadioBridge.jar` вызывает
`fmod.javafmod` либо точную доступную `javafmodJNI`:
- `FMOD_System_CreateSound(file, FMOD_CREATESTREAM | FMOD_2D/3D)` —
  аудиопоток, вместо заранее декодированного целиком WAV;
- `FMOD_System_PlaySound` и `FMOD_Channel_SetPosition(channel, ms)` —
  начало с текущей позиции, без лишней минуты «отложенного» звука;
- `FMOD_Channel_SetVolume`, `FMOD_Channel_Set3DAttributes` —
  громкость, автомобиль и физическое положение источника;
- `FMOD_Channel_Stop` и `FMOD_Sound_Release` — обязательное освобождение.

На выходе из слышимости, при выключении/нулевой громкости, смене
частоты, конце песни и отключении клиента Java-канал освобождается.
Для перемещения между двумя 3D-радио источник может сменить координаты,
без повторного открытия. Для смены 2D/3D источник открывается заново с
новым **актуальным** смещением, а не с нулевой секунды.

Лимиты: ровно `north_track_01`–`north_track_41`, только WAV,
только локальный каталог **активного** SiegerRadio мода из
ZomboidFileSystem.getModDir("SiegerRadio"), максимум 32 MiB на файл,
не более одного клиентского потока от радиостанции. Ни URL, ни имён
произвольных файлов, ни путей от сервера Java-мост не принимает.

Источники: официальные FMOD Core API (createStream, Channel.setPosition,
FMOD_CREATESTREAM, FMOD_TIMEUNIT_MS); открытый ZombieBuddy Modding Guide.
Поддержка этих вызовов **на конкретной версии javafmod** ещё требует
тестирования через запуск игры. Мод сознательно не изменяет PZ классы.

## Что требуется от владельца на клиенте

1. На своей Windows-машине обновить **официальный ZombieBuddy** до
   выпуска с исправлением Build 42.21 (issue zed-0xff/ZombieBuddy#53);
   установщик Java-agent отдельно от Workshop. Для Linux/Mac следовать
   официальной инструкции. Загрузка произвольного Java JAR предоставляет
   полный доступ к системе; перед подтверждением проверить его исходники.
2. Для сборки установить JDK, способный читать текущий `projectzomboid.jar`
   (для Build 42.21 Java 25). Получить сам JAR из **своей установленной**
   игры, никогда из случайных URL.
3. В checkout, где доступны локальные WAV всех 41 композиций:

```bash
python3 scripts/radio_assets.py check
python3 scripts/radio_bridge_build.py --game-jar /path/to/projectzomboid.jar
python3 scripts/radio_pack.py build --output /path/new/SiegerRadio-<VERSION>.zip
python3 scripts/radio_pack.py verify /path/new/SiegerRadio-<VERSION>.zip
```

Программа сборки **не загружает** сторонние JAR, не подменяет игру и
не перезаписывает предыдущий выходной JAR. Он исключён из Git и должен
входить в проверенный ZIP; упаковщик откажется создавать архив без него.

4. Закрыть игру, установить один целостный обновлённый пакет SiegerRadio,
   включить ZombieBuddy + SiegerRadio. На первом старте проверить в диалоге
   ZombieBuddy путь и SHA-256 **своего** JAR, явно одобрить только его.
   Старые пакеты SiegerRadio не совместимы с новой версией каталога.
5. Прогнать тесты на `story_test` с двумя клиентами: вступить в эфир
   с 30–60-й секунды песни, уйти за 12 клеток и вернуться, выключить и
   включить, переключить частоту, переключиться между радио в машине и
   переносным устройством, проверить конец/начало следующих двух песен.
   Проверить настройки общей громкости и 3D-затухания, client console.txt,
   кадровую частоту и рост RAM после прослушивания пяти разных треков.

## Коррекция близкого 3D-звука без перехода в 2D

Java-мост для установленного и автомобильного радио оставляет настоящий
FMOD_3D поток. Его полный ближний радиус стал **4** вместо **1** единицы,
дальний — по-прежнему **12**. Это уменьшает слишком быстрое затухание
у радиоприёмника, но не гарантирует компенсацию поворота камеры Viewpoint.
Переносное радио и исходники музыки не менялись.

См. `docs/STORY_RADIO_3D_AUDIO_RU.md` для теста, при котором вращение
на месте отделяет направленную потерю громкости от расстояния/окклюзии.
`FMOD_3DSpread` не имеет надёжного эффекта для наших моно-WAV; подмена
этого решения на невидимый 2D канал запрещена требованием владельца.

## Критерии допуска

- Новое включение посреди песни слышит композицию приблизительно с текущей
  позиции (ошибка не более сетевой задержки + половины интервала поиска);
  новая композиция **не** начинает играть с нулевой секунды после возврата.
- Нет звука без включённого приёмника, нет открытых FMOD каналов, когда
  радиоприёмник выключен или игрок вне зоны.
- Нет неподконтрольного роста RAM после каждого следующего трека.
- Клиент 2 слышит ту же композицию и примерно ту же фазу, не звучит
  ничего с другой частоты/с нулевой громкостью/без питания.
- Отсутствующий/неодобренный Java JAR и неправильные методы FMOD
  безопасно отклоняются, без постоянных retry или спама логов.

**Пока эти условия не подтверждены в игре, PR не мержить и на VPS
не развёртывать.** GitHub-изменения не выполняют rollback или restart,
не меняют сохранения и ничего не делают с `road_home`.
