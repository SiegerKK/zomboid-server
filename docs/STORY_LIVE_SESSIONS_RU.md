# Story Director: live-сессии с бэкапами до и после правок

**Статус:** экспериментальная функция PR #8. Offline CI пройден, **реальная игровая проверка на Build 42.21.0 ещё обязательна**. Не применять к `road_home`, пока сценарий не проверен на `story_test`.

## Задуманный цикл работы

1. **Начало сессии.** Оператор согласует короткое окно обслуживания, проверяет `players=0`, штатно останавливает сервер, создаёт проверенный SHA-256 cold backup **ДО** изменения, включает при необходимости Story runtime и возвращает тот же мир в фон.
2. **Работа во время игры.** Новые проверенные JSON-сцены с уникальными ID передаются серверному Lua через закрытую файловую очередь, без RCON eval и перезапуска сервера. Допустимы только записки `note` и обычные предметы `loot` на земле или в точном контейнере. Игроки могут быть онлайн.
3. **Подтверждение.** Сервер возвращает `applied`, `already`, `pending` (участок не загружен) либо `error` для каждого действия. При неуспешных и незавершённых действиях завершение сессии запрещено. Снимок сцены и квитанции сохраняются в закрытом каталоге мира.
4. **Фиксация.** Снова при `players=0` создаётся проверенный cold backup **ПОСЛЕ**, сервер возвращается в фон, и рядом с архивом записывается root-only `.story-commit.json` с контрольными суммами обоих бэкапов, UUID сессии и применёнными сценами.

Слово **commit** здесь означает зафиксированное игровое состояние, **не Git commit**. Мировые сохранения и приватные отчёты не помещаются в публичный GitHub.

## Команды

```bash
sudo pz status

# При согласованном коротком простое и нуле игроков:
sudo pz story live-begin story_test --yes

# Теперь сервер снова работает, игроки могут играть.
# Сцена — проверенный root-owned JSON в story/scenes/; применяются только enabled действия.
sudo pz story validate clinic_live_001
sudo pz story preview clinic_live_001
sudo pz story apply-live story_test clinic_live_001 --yes
sudo pz story live-status story_test

# Для pending: игрок должен войти в соответствующую область.
# Для error: не фиксируй сессию, разберись в неисправности.

# После просмотра результата игроками и повторной проверки RCON players=0:
sudo pz story live-commit story_test --yes
sudo pz story live-status story_test
```

Для производства можно будет использовать `road_home`, но **только после отдельного успешного тестирования и согласия владельца**. Переключать активные мировые слоты в ходе одной live-сессии запрещено.

## Безопасность и ограничения

- Начальный и конечный **согласованные cold backup** требуют остановки игрового контейнера. Нельзя безопасно выдавать копию файлов активно записываемого мира за согласованный холодный бэкап. Между этими точками правки идут без остановки.
- Учитываются только настоящие загруженные клетки: отсутствие клетки = `pending`, а не внезапная генерация чанка. Очередь содержит не более 32 действий и 128 KiB. Обработка идёт с ограниченной частотой внутри game-loop.
- JSON строго валидируется: название слота, ID сцены и операций, реальные координаты, существующий класс/спрайт/индекс контейнера, допустимый item ID. Нет `loadstring`, `dofile` по пользовательскому тексту, RCON exec, новых портов или клиентского Lua.
- `barricade`, `infected`, `decor`, `construction`, удаление предметов и структур **не поддерживаются live-режимом**. Их нельзя включать, обойдя проверку.
- Идемпотентность лучшей попытки: метки действий и предметов ограничивают дублирование при перезапуске. Это **не транзакция ACID**: при сбое между добавлением и отметкой состояния возможны частичные действия. Никакого автоматического опасного отката. Для отката загружай исходный before-archive **в новый слот**.
- При обычном `pz load` сцены и незавершённые request/response получают расширение `.needs-review`, чтобы случайно не исполниться в восстановленном мире.
- Протокол использует root-only `data/Lua/SiegerStoryLiveRequest.txt` и `SiegerStoryLiveResult.txt`; при остановках очереди переносятся в приватный архив. Выполнение не запускает произвольный Lua из GitHub.
- Приложение и сервер должны проверить соответствие UUID, scene ID, action IDs и SHA256 запроса. Хеш в квитанции **привязывает запись журнала**, а не является цифровой подписью/game-side verification тела; источник доверия — root-owned проверенные файлы.

### Хранимые файлы

- `story/storyctl.py` — строгая валидация/превью JSON.
- `story/livectl.py` — управление сессией, защита очередей и контрольные суммы.
- `story/runtime/SiegerStoryDirector.lua` — обработчик разрешённых действий на сервере.
- `/srv/zomboid/worlds/<world>/story/live/session.json` — личный журнал.
- `/srv/zomboid/worlds/<world>/data/Lua/SiegerStoryLiveRequest.txt` и `SiegerStoryLiveResult.txt` — приватный локальный обмен.
- `/srv/zomboid/backups/worlds/<world>/world-*.tar.gz` — архивы before/after и `.sha256`.
- `*.story-commit.json` — журнал фиксации рядом с after-архивом.


## Готовый тестовый сценарий клиники

В `story/scenes/clinic_live_001.json` добавлен **только для мира `story_test`** подтверждённый контейнер: X=3171, Y=12141, Z=0, `object_index=2`, `container_index=0`, sprite `location_business_office_generic_01_33`, class `IsoObject`. Сценарий добавляет записку врача из трёх страниц, два бинта и дезинфицирующее средство. JSON помечен `enabled=true`, но **это не означает, что он уже применён**: его не исполняет один только Git pull, потребуются открытая live-сессия и `apply-live`.

Перед испытанием сравнить объект с фактическим отчётом `scan-player` — индексы меняются при изменении карты. Если мир уже содержит эту сцену или шкаф был изменён, **создать новый ID/слот или остановить тест**, не подставлять произвольный index. Развернуть только после проверки реального pinned Build 42.21 API и выполнения шага с backup «ДО».
