# Исправление 3D-радио после клиентской видеопроверки

## Статус

Версия `sr17-v1-9c6afcc4b253`, runtime_revision=8, PR #24.
Предыдущий вариант Spread=120 не прошёл игровую приёмку владельца.
Новый код и пакет подготовлены; **в работающую игру и на VPS не установлены**.
Повторное прослушивание и езда с реальными клиентами обязательны.

## Что подтверждено

- Локальная запись 108.768 s, 1920×1080, stereo AAC 48 kHz. Есть осмотр
  машины, вращение взгляда и поездка. Видео/извлечённое аудио остаются локально.
- В первых секундах распознана north_track_09 (корреляция ~0.794 с оригиналом).
  Оценка вклада этой музыки в смешанный игровой звук падает примерно на 30 dB
  около 42–49 s. Это оценка из записи с мотором/окружением, не прямой замер FMOD.
- Живой PulseAudio поток ProjectZomboid64: **6ch / 32000 Hz**,
  FL/FR/FC/LFE/SL/SR. Выход наушников — **2ch / 48000 Hz**, FL/FR,
  без перекоса уровня L/R. Настройки звуковой системы не менялись.
- Реальный native FMOD_System_Init PZ задаёт software speaker mode=6 (5.1).
  Viewpoint Hearing.listen переориентирует listener через Studio Listener3D.
- На настоящем libfmod 2.03.09 источник сзади при native 5.1 даёт сигнал
  в SL/SR, а не FL/FR. Это подтверждённый маршрут риска при выводе в наушники;
  конкретные коэффициенты системного downmix пока не измерены. Само наличие
  5.1→2 не доказывает дефект любого PulseAudio downmix.
- Spread=120 разносит компоненты stereo на ±60° вокруг точки источника:
  отсюда возможны искусственные направления музыкальных партий. Это не
  компенсация rear attenuation. Старую попытку не считать исправлением.
- В прежнем Lua координаты машины обновлялись вместе с дорогим поиском радио
  раз в 30 ticks (~600 ms при 50 FPS). Движущийся listener обгонял старую точку
  источника: это согласуется с пропаданием на ходу и возвратом после остановки.
  В старом логе нет native-stream errors, но нет и достаточных start/stop
  метрик, чтобы утверждать, что каждый обрыв был только затуханием.

## Новый локальный для SiegerRadio путь

Один FMOD_CREATESTREAM | FMOD_3D канал, физические X/Y и Z×3
(тот же масштаб этажей, что у штатного PZ listener/emitter), near/far=4/12.
Gain и окклюзия не меняются. Spread по умолчанию **0°**: одна физическая точка.
Два оригинальных канала файлов сохраняются; FMOD позиционирует 3D-точку
обычным способом. Portable остаётся прежним настоящим stereo FMOD_2D.

Для автомобильного/стационарного радио создаётся **одна частная mixer group**
SiegerRadioStereo. Её FADER получает channel format FL|FR / 2 / STEREO.
Это шина одного существующего потока, не второй музыкальный источник.
Не меняются устройство, глобальный software format, listener, Viewpoint,
звуки зомби/оружия/шагов/машин или master group.

В отдельной NOSOUND_NRT системе настоящей игровой FMOD (без аудиоустройства):

| Угол listener | Native stereo RMS L/R | Частная stereo-шина при global 5.1 |
|---|---|---|
| 0° | .1075 / .1075 | .1075 / .1075 |
| 90° | .1519 / 0 | .1556 / 0 |
| 180° | .1074 / .1074 | .0759 / .0759 |
| 270° | 0 / .1520 | 0 / .1558 |

Задний источник в частной шине слышим в обоих каналах; примерно −3 dB
относительно переднего, а не тишина. Это синтетический тест native DSP,
**не прослушивание модифицированной игры**. Контрольный посторонний источник
по-прежнему выдаёт сигнал только в задние SL/SR, global format остаётся 5.1.
То есть остальные игровые звуки не перенаправлены в stereo.

ПКМ при активном физическом радио → `SiegerRadio: output A/B`:
`Stereo headphones (3D)` / `Native surround (3D)`. Переключается группа
того же канала, без нового PlaySound/seek. Native оставлен для настоящего 5.1
и сравнения. Прежние Spread-предустановки оставлены как явная диагностика,
не как рекомендуемое исправление; основной тест проводить со Spread=0.

Если optional group/direct-buffer API отсутствует, остаётся native 3D с
`stereo_bus_unavailable`/`stereo_bus_failed`, а не ложный PASS.

## JNI: проверять семантику, а не только Java-сигнатуру

FMOD_System_PlaySound(long,long): второй аргумент — **paused**, не группа.
Новый поток стартует paused=1, затем настраиваются маршрут, позиция, seek
и уровень; только после этого SetPaused(channel,0). Это исключает стартовый
фрагмент песни с нулевой секунды.

FMOD_DSP_SetChannelFormat(long,long,int,long): mask и speaker mode в этом
старом SWIG JNI — **указатели на int32**, а не значения 3. Используется
ровно один приватный direct ByteBuffer(8), native byte order, проверенный
LWJGL MemoryUtil.memAddress; pointer outputs очищаются и проверяются.
Lua не получает указателей, путей, произвольных параметров DSP или классов.

При подготовке изолированного probe неверное предположение об enum pointer
в JNI SetOutput/SetChannelFormat вызвало SIGSEGV отдельного тестового JVM.
Исправлено до распространения: реальные вызовы прошли повторно, mock теперь
проверяет адреса и значения int32, а не ошибочно принимает литералы enum.
Запущенная игра и VPS этими пробами не затрагивались. Краш-логи локальные.

Проверено на установленном Linux B42.21.0; другую native ABI не считать
поддержанной по одному совпадению имён методов. Для Windows/macOS нужна
отдельная проверка клиента и актуальной библиотеки.

## Движение и ресурсы

- Сначала ищется радио `player:getVehicle()`; временно пустой Set машин
  на границе чанков и отстающие render-координаты героя не теряют его машину.
- Cached vehicle part проверяет питание/частоту/volume, координаты существующего
  FMOD источника обновляются **каждый tick**. Полный поиск остаётся throttled.
- JNI Set3DAttributes пропускается при неизменной позиции; SetVolume — при
  неизменном gain. Нет пересоздания или seek на каждом движении.
- Выключение/retune/потеря питания/слышимости освобождают канал, группу и sound.
  В возврате используется текущая позиция эфира. Portable без новой шины.
- STREAM START/STOP и SPATIAL/OUTPUT логи содержат тип/clip/offset/status,
  без координат баз и содержимого инвентарей.
- 41 музыкальный WAV побайтово неизменён; глобальная нагрузка не профилировалась.
  Добавлена одна mixer group/небольшой stereo buffer, а не второй декодер.
  FPS/CPU/RAM в реальной поездке всё ещё нужно проверить.

## Проверки и воспроизведение

PASS: локальный workflow (без root smoke), Python/Lua/Compose, Java mock
(один stream, paused setup, указатели enum, toggle без seek, cleanup),
negative optional bus/spread API, 90 ticks движения по 3 tiles с пустым Set
и неподвижными координатами игрока; четыре harness на настоящем game Kahlua.
Root smoke локально требует sudo; полный root smoke выполняется в Actions.

Дополнительно PASS на настоящей библиотеке и настоящем game JNI, не моках:

```bash
python3 tests/test_radio_native_spatial.py --library /path/to/natives/libfmod.so
# JDK 25, настоящий установленный game JAR и собранный мост:
javac -cp "$GAME_JAR:$BRIDGE_JAR" -d /tmp tests/RadioNativeStereoProbe.java
java --enable-native-access=ALL-UNNAMED -Djava.library.path="$NATIVES" \
  -cp "/tmp:$GAME_JAR:$BRIDGE_JAR" RadioNativeStereoProbe "$NATIVES" /tmp/synthetic.wav
```

Оба probe создают отдельную NOSOUND_NRT систему, не подсоединяются к живой
игре, не используют microphone/device output/сохранения. WAV должен быть
синтетическим, не музыкой. Java probe проверяет реальную MemoryUtil/JNI
семантику, private bus, toggle и cleanup; это не тест modRoot/мультиплеера.
