# Независимый административный runtime SiegerAdmin

## Разделение

Один репозиторий, один Bash-менеджер `pz`, без новой панели или сервиса.

- `mods/SiegerRadio`: клиентский звук, Java/FMOD, станция и эфирные команды.
  Каталог, 41 музыкальная композиция и существующий handshake не меняются.
- `mods/SiegerAdmin`: Story Director, сканирование, операции над персонажем,
  инвентарём и транспортом, batch, TLOU-диагностика, часы, private bundle loader.
  Нет зависимости от SiegerRadio, музыкальных файлов, Java JAR или ZombieBuddy.
  Копии серверного Lua нужны клиентам для штатной B42 проверки checksum.
- `story/runtime`: единый исходник серверного Lua. `scripts/admin_assets.py`
  генерирует проверяемые публичные копии в SiegerAdmin. Профили и клиентский
  обработчик персонажа находятся непосредственно в SiegerAdmin.
- `story/*ctl.py`, `story/timecontrol.py` и `pz`: привилегированный CLI на VPS,
  доступный codex-pz через существующий ограниченный gateway. Он не выдаётся
  игровым клиентам. Файлы запросов остаются приватными под world/data/Lua.

SiegerRadio больше не содержит административного Lua. Его эфирное расширение
по-прежнему проверяет разрешённый Story-контекст; административный пакет не
зависит от радио. Новые административные функции обновляют только SiegerAdmin.

## Docker и отсутствие двойного выполнения

`compose.story.yaml` монтирует локальный SiegerAdmin read-only и приватный
SiegerStoryBundle.txt как данные; активирует Mod ID через PZ_STORY_ADMIN_MODS.
**PZ_STORY_ADMIN_MODS обязателен** и должен содержать весь исходный MODS-профиль
плюс SiegerAdmin. Менеджер `pz` строит его автоматически; прямой Docker Compose
без этого параметра теперь отказывает, а не отключает TLOU/Viewpoint.
`compose.radio.yaml` сохраняет эти mounts и добавляет только радиопакет.
Никаких инъекций в ванильный media/lua/server. Runtime audit также переехал
в административный пакет; для миров без Story больше нет ванильного audit mount.
Workshop ID и содержимое Workshop не меняются, музыка не переносится на VPS.
`pz` добавляет локальные Mod ID поверх существующего профиля, не переписывая его.

## Часы онлайн

```
pz story time show story_test
pz story time status story_test
pz story time set story_test 07:30             # preview
pz story time set story_test 07:30 --yes
pz story time advance story_test 360 --yes    # скачок вперёд на 360 минут
pz save-live
```

`show` ставит read-only запрос; `status` читает ответ по тому же request ID.
Операции выполняются на игровом потоке через OnTickEvenPaused, максимум один
опрос в секунду, без паузы/перезапуска сервера. Этот event присутствует в
GameStates.IngameState.updateInternal настоящего установленного B42.21 JAR.
API GameTime get/setTimeOfDay, setLastTimeOfDay, day/month/year/nightsSurvived
проверены по его байткоду. Изменение set сохраняет дату; advance принимает
1..1440 минут и правильно переводит календарь/счётчик ночей (граница суток
выживания — 07:00). Это скачок часов, не ускоренная симуляция событий мира.
Не меняются скорость игры, погода, возраст еды или состояние игроков вручную.

Без `--allow-players` изменение отклоняется, если появился хотя бы один игрок.
Флаг является отдельным явным согласием CLI-оператора, не клиента. Срок запроса
30 секунд; durable guard записывается до изменения и блокирует повторы после
рестарта или частичного сбоя. Ошибка требует изучения журнала; новое действие
после неё разрешается только с `--acknowledge-failed`. Ни Lua eval, ни новые
публичные порты, ни клиентские mutation-команды не добавляются.
Проверка ответа CLI не заменяет наблюдение часов двумя игровыми клиентами.

## Миграция клиента

Нужны одновременно чистая актуальная папка SiegerRadio и отдельная SiegerAdmin.
Нельзя просто наложить новые файлы поверх старого SiegerRadio: старые admin Lua
останутся и могут исполняться дважды. `pz start` для radio-enabled Story мира
теперь сверяет весь модульный состав через `admin_assets.py check` и отказывает
при старых/лишних Lua-файлах. Сохраните свою старую папку вне Zomboid/mods,
замените её полной новой папкой; установите/активируйте SiegerAdmin. Музыка
остаётся в SiegerRadio. Не устанавливайте старые patches после миграции.
Не отключайте DoLuaChecksum и не копируйте приватный bundle в клиентский ZIP.

Сначала подготовьте согласованные клиентские пакеты, затем при отсутствии
игроков: cold backup, deploy точного CI-passed commit, start story_test.
Не мигрируйте road_home и не восстанавливайте checkpoints автоматически.
Старый offline `pz story clock` остаётся как отдельный аварийный инструмент
для проверенного формата сохранения и не нужен для нового online режима.

PASS (локально): 29 Python test files; 31 Lua syntax/runtime checks; отдельные
проверки целостности admin pack, отсутствия admin Lua в radio, Compose/mounts,
пограничных дат (leap/year), connected-player отказа, expiry, replay и restart.
PASS: новый clock fixture выполнен Kahlua VM настоящего установленного JAR,
SHA-256 e1a69eb743ede60b213a0fe7f8b83d4fcab773036d256cc4543a336f3b058a33.
Это тест API-формы/VM с fixtures, не приёмка сетевой репликации.

BLOCKED до согласованной миграции клиента/серверного развёртывания: ordinary
checksum login нового двухмодульного комплекта, online clock на реальном
пустом PAUSE_EMPTY сервере и часы у двух клиентов, повторная приёмка сканов,
инвентаря и радио. Старый сервер остаётся работающим до этой миграции.

Фактически ранее выполнено независимо от этой реорганизации: на story_test
установлено 07:30, дата сохранена 1993-12-01, штатный RCON save и readback
map_t.bin подтверждены. Эта операция была в commit bf7f388; Lua не менялся.

## Строительство поселений по этапам

Новый инструмент `pz story build` создаёт настоящие серверные IsoThumpable /
IsoDoor / IsoWindow / IsoGenerator объекты, а не декоративные спрайты вместо
стен или источников питания. Он поддерживает именованные этапы,
зависимости и приватные JSON-манифесты, dry-run по умолчанию, предварительную
проверку каждой операции до первого изменения, точное удаление объектов,
сетевую передачу и журнал завершённых стадий. Документация:
[STORY_SETTLEMENT_CONSTRUCTION_RU.md](STORY_SETTLEMENT_CONSTRUCTION_RU.md).

## Универсальный атлас зданий и плотности

Одноразовая read-only перепись метаданных всех зданий выбранной области:
`pz story atlas capture WORLD --bbox X0,Y0,X1,Y1 --yes`.
Экспортируемый atlas содержит точные прямоугольники комнат по этажам,
приблизительный перечень загруженных чанков и исходные границы зданий.
`pz story atlas analyze` сопоставляет эти данные с уже существующими
`zombies report` или `tlou roster`; не пересчитывает AI и не загружает карту.
Полная инструкция: [SIEGER_ATLAS_RU.md](SIEGER_ATLAS_RU.md).
