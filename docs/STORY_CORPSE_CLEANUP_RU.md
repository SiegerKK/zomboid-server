# Точечное удаление трупов через batch

Новый target `corpse` удаляет только выбранный `IsoDeadBody` в загруженной
клетке. Пример синтаксиса (координаты условные, не план для мира):

```json
{"schema":1,"world":"story_test","actions":[
  {"target":"corpse","at":[100,200,0],"static_index":0,
   "changes":[{"op":"remove"}]}]}
```

`static_index` берётся из свежего AreaScan, не из списка обычных объектов.
Доступна ровно одна операция `remove`. Проверяются загруженная клетка,
индекс, класс, отсутствие повторного выбора тела и штатный API удаления.
Весь batch проходит preflight до первой записи. При исполнении сохраняется
ссылка на конкретное тело: сдвиг индексов после удаления другого трупа
не изменяет выбранный объект. Перед удалением повторно проверяется его
присутствие в static moving list.

Используется `IsoGridSquare:removeCorpse(body, false)`. В установленном
Build 42.21 байткод метода при `GameServer.server && !boolean` отправляет
`RemoveCorpseFromMap` через `INetworkPacket.sendToRelative`, затем вызывает
`removeFromWorld` и `removeFromSquare`. Значение `true` подавляет эту передачу
и здесь не используется. Инвентарь тела удаляется вместе с телом; возвращения
предметов на землю нет. Трупы игроков также относятся к IsoDeadBody: оператор
обязан согласовать выбор территории и удаление. Живые зомби не затрагиваются.

Команды: `pz story batch preview WORLD --file PLAN.json`, затем
`pz story batch apply WORLD --file PLAN.json --yes` и `batch status WORLD`.
Нельзя объявлять удаление завершённым по QUEUED: нужен complete и новый скан.
Незагруженные клетки не подгружаются автоматически. Изменения без транзакции:
при partial_possible нельзя слепо повторять запрос. Нужен контрольный backup.

Проверки исходников: Python-компилятор и Lua fixture проверяют фиксированный
протокол, неверный класс, повторный индекс, полный preflight, две смерти на
одной клетке со сдвигом индекса, false для сетевого флага и отсутствие replay.
Это не игровая приёмка; фактическое удаление и видимость клиента требуют
развёртывания согласованной версии SiegerAdmin и реального теста.
