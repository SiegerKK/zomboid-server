# NORTHBOUND: музыкальный пакет владельца

Каталог содержит 41 трек из локального `radiomusic.zip` (159 минут),
ID `north_track_01`–`north_track_41`, плюс прежний `test_tone` вне плейлиста.
Названия, SHA-256 исходников и длительности находятся в
`story/radio/owner-tracklist.json`; SHA-256 преобразованных PCM-файлов —
в `story/radio/catalog.json`. Ни один трек не обрезан. Станция — 101.2 МГц.

Версия клиентского пакета: **sr17-v1-f547aa6dd6f5**.
Музыка преобразована штатным `radio_assets.py add --music`: mono WAV,
PCM 16-bit / 22050 Hz. Бинарные музыкальные файлы распространяются отдельно,
а не через историю Git. После `git pull` одних исходников недостаточно.

## Сборка и проверка

На машине с подготовленными WAV:

```bash
python3 scripts/radio_assets.py check
python3 scripts/radio_pack.py build --output /path/SiegerRadio-sr17-v1-f547aa6dd6f5.zip
python3 scripts/radio_pack.py verify /path/SiegerRadio-sr17-v1-f547aa6dd6f5.zip
```

ZIP включает весь мод `SiegerRadio/`, Lua, sound definitions и 42 WAV.
Проверка сверяет каждый файл с текущим кодом и каталогом, отклоняет
неожиданные/повторяющиеся пути, повреждения и превышения размера.
Установка сначала проверяет весь архив и требует новый каталог назначения:

```bash
python3 scripts/radio_pack.py install /path/SiegerRadio-sr17-v1-f547aa6dd6f5.zip \
  --destination /path/new/SiegerRadio
```

Клиент: закрыть игру, сохранить старый каталог мода отдельно, установить
новый `SiegerRadio` в папку модов и запустить игру заново. Все игроки должны
иметь одинаковый пакет. Треки не передаются с VPS во время игры.
Не публиковать автоматически в Workshop.

На VPS музыкальные WAV устанавливаются отдельно от Git в
`/opt/zomboid-server/mods/SiegerRadio/42/media/sound/SiegerRadio/`.
При установке в уже существующий checkout использовать временный НОВЫЙ
каталог, сверить пакет, перенести только проверенные отсутствующие WAV;
не заменять весь checkout и не менять секреты/сохранения/Workshop.
Перед игровым рестартом — согласование окна и RCON players=0.
После установки обязательно выполнить строгий `radio_assets.py check`.

## Что проверяет CI

`radio_assets.py check --allow-missing-external` явно разрешает отсутствие
только WAV с `external_asset: true` и сообщает число **непроверенных**
внешних файлов. Генерируемые Lua, версии и каталоги проверяются всегда;
встроенный `test_tone.wav` обязателен. Это проверка кода и метаданных,
а не проверка недоступных CI музыкальных байтов.
На рабочей станции/VPS требуется строгая проверка без этого флага.

## Игровая приёмка

Автоматические тесты не подтверждают слышимость через FMOD.
После установки одинакового пакета: проверить HELLO, переносной приёмник,
стационарный IsoRadio, автомобиль, питание/смену частоты/расстояние,
автоматическую смену двух песен и два клиента. Позднее подключение использует native seek к позиции текущей композиции;
нужны проверка FMOD API на двух клиентах и разрешение клиентского JAR.

```bash
sudo pz story radio station status story_test
sudo pz story radio station start story_test --yes
sudo pz story radio station stop story_test --yes
```

Старые сюжетные сцены не применяются повторно. В существовавшем баре
ранее лежал инвентарный HamRadio1; обновление не превращает его в мебель.
Для настоящего IsoRadio потребуется отдельная проверенная постановка.

## Исправление владения FMOD-источником

В bytecode IsoWorld из pinned image подтверждено:
`takeOwnershipOfEmitter()` удаляет emitter из списка `currentEmitters`;
автоматический `IsoWorld.update()` вызывает `tick()` только для оставшихся.
Клиентский SiegerRadio теперь вызывает `emitter:tick()` сразу после постановки
звука и на каждом OnTick, а не только во время периодического поиска радио.
При ошибке запуска источник очищается и возвращается движку.
Регрессионный receiver-тест проверяет 11 tick-вызовов за запуск + 10 кадров.

`runtime_revision` включён в hash рукопожатия, чтобы исправленная клиентская
логика отличалась от предыдущей версии с теми же музыкальными файлами.
При следующих несовместимых изменениях клиента увеличивать это поле;
генератор обновляет все три Lua версии. При нулевой ревизии старые отпечатки
сохраняются. Это не заменяет реальную проверку слышимости в игре.

## Приёмка 101.2 и исправление Java Set

В штатном RWMChannel.lua закреплённой игры шаг пресета равен 0.2 МГц.
Постоянная частота изменена на 101.2 МГц, включая клиент, станцию,
радиоканал и будущую фурнитуру. Текущий мир автоматически не меняется.
Клиентский журнал выявил `Object tried to call nil` на vehicles:get(i).
IsoCell.getVehicles() в точном JAR возвращает java.util.Set; обход исправлен
на ограниченный iterator(), как в действующем Story AreaScan. Receiver mock
теперь использует Set без get(), включая непустую коллекцию автомобилей.
Сохранение частоты позиционного CUE исправлено: контроль приёмника использует
реальную частоту команды. Длинные разовые CUE принимают до 720 секунд;
терминально отклонённый запрос не разбирается повторно на каждом тике.
Код требует обновления клиентского мода и согласованного игрового рестарта.
Проверка слышимости на реальном клиенте пока FAIL, исправления ожидают приёмки.

## Потоковая аудиосистема

Новая версия `sr17-v1-f547aa6dd6f5` требует компиляции только CLIENT-моста
`scripts/radio_bridge_build.py --game-jar /path/to/projectzomboid.jar`.
Исходники в `mods/SiegerRadio/42/media/java/src/`, бинарник не хранится в Git.
Загрузку нового Java-кода ZombieBuddy запрашивает у игрока при входе;
нужно явно одобрить. Старый Lua/ZIP несовместим. Сначала убедиться, что
проверка javafmod прошла и нет бесконечных ошибок и утечек, только потом тестировать
включение, позднее подключение, автомобиль и позиционный звук.

## Исправление сильной L/R-панорамы в салоне автомобиля

При подтверждённом повороте камеры в машине предпочтителен
**настоящий стерео-3D источник с FMOD Spread**, а не смесь с 2D.
Java-мост добавляет опциональный native `set3DSpread` с локальным
переключением 0/60/90/120/150/180°, по умолчанию 120° только для
2-канального PCM. Нынешний пакет содержит mono, поэтому Spread
на нём не обещает исправления.

Сначала подготовить ровно один stereo-образец **из исходного ZIP**:

```bash
python3 scripts/radio_stereo_prepare.py --archive /path/radiomusic.zip \
    --track north_track_38 --output /path/new-stereo-test --yes
```

Файлы `catalog.candidate.json`, `pcm/` и `generated/`
создаются в новой директории и **не активируют** музыку на сервере.
Новый SHA/клиентский handshake нужно подтвердить и оформить
в отдельной тестовой сборке; без оригинала ни один WAV не менять.
Подробности: `docs/STORY_RADIO_3D_SPREAD_CONTINGENCY_RU.md`.
