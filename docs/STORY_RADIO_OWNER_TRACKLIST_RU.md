# NORTHBOUND FM — актуальный релизный контракт PR #24

**Текущая версия исходников:** `sr17-v1-023e01823321`, `runtime_revision=10`.
Частота — **101.2 МГц (101200 кГц)**, 41 стереотрек PCM 22050 Hz/16-bit/2ch,
исходники владельца без публикации WAV в GitHub. Все 41 композиции
подготовлены локально с постоянной громкостью примерно -19.5 LUFS.
`test_tone.wav` — короткий отдельный сигнал, не часть плейлиста.

## Клиент и сервер

Всё воспроизведение музыки идёт только через локальный Java/FMOD STREAM
с `setPosition(ms)`, а не через GameSound; остановленный приёмник
не держит беззвучный декодер. Код Bridge ABI:
`siegradioBridgeBuild() == "radio-merge10"`. Lua при HELLO
проверяет реально разрешённый и совместимый ZombieBuddy Java-мост;
сервер требует одновременно точные `version` и `build`.
Старые ZIP/JAR даже с правильным названием мода не считаются готовыми.

Стационарное радио: ближняя полная зона **4**, максимум **12** клеток.
Автомобиль: ближняя зона **4.8** (+20%), максимум **30** клеток,
включая слушателя снаружи машины; дальность FMOD и поиск машин совпадают.
Переносное радио — локальный личный звук, без дистанционного 3D-затухания.
Короткий `test_tone` имеет отдельное GameSound-определение для машины
с `distanceMax=30`, у неподвижного радио — прежний `distanceMax=20`.
**Полные 41 песни намеренно не регистрируются в GameSounds**, чтобы не
запускать большие WAV старым eager-путём; длинные CUE запрещены.

Управление серверной станцией: `sudo pz story radio station start story_test --yes`
только после установки совпадающей версии пакетов и с явным разрешением.
Файлы радиостанции и прочие checksum Lua находятся в
`SiegerRadio/42/media/lua/server/`; приватные данные сюжета отдельно
монтируются как `SiegerStoryBundle.txt`, не исполняются как Lua.
Серверный `mod.info` через Compose не должен загружать клиентский JAR.

## Сборка только на компьютере с проверенными WAV и игровым JAR

```bash
python3 scripts/radio_assets.py check
python3 scripts/radio_bridge_build.py --game-jar /path/to/projectzomboid.jar
python3 scripts/radio_pack.py build --output /path/new/SiegerRadio-sr17-v1-023e01823321.zip
python3 scripts/radio_pack.py verify /path/new/SiegerRadio-sr17-v1-023e01823321.zip
```

Не перезаписывать существующий пакет поверх игры. Клиенту сначала полностью
закрыть Project Zomboid, заменить **всю** папку `SiegerRadio`, проверить
SHA итогового ZIP и отдельно одобрить новый JAR в ZombieBuddy.
Музыка и скомпилированные JAR остаются локально: в Git размещены только
метаданные SHA, Lua/Java исходники, конфигурация и тесты.

Последний нормализованный набор 41 WAV от ревизии 9 **не менялся** при
переходе на 10. При пересборке кода/Java-моста ZIP получает новый хеш;
не переиспользовать SHA старого ZIP.

## Тесты перед развёртыванием

CI проверяет генератор, контрольное совпадение Lua,
Python/Lua5.1/Java mock, Compose, стабильность одного FMOD-канала,
переход furniture→car→furniture, короткий CUE и границы 30/12.
CI без локальной музыки использует явный режим
`radio_assets.py check --allow-missing-external`;
на реальном клиенте и перед сборкой ZIP нужен **строгий** `check`.

Реальная приёмка всё ещё необходима: два обычных игрока Linux/Windows с
`DoLuaChecksum=true`; музыка в стоящей/движущейся машине, поворот
головы, громкость/реальные 3D-наушники, 12/30 клеток, верхний этаж,
вход посреди песни, CUE поверх станции, замер звуков двигателя/зомби
с priority32, нагрузка RAM/CPU и завершение двух треков.

**Git merge не развёртывает мод, не перезапускает VPS, не загружает WAV
и не меняет `story_test` или `road_home`.**
