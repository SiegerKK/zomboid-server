# Часы текущего дня без обновления клиентского мода

Команда `sudo pz story clock story_test 07:30` показывает preview на чисто
остановленном сервере. `--yes` атомарно устанавливает часы того же календарного
дня. Это не симуляция пропущенных часов. Lua и клиентский ZIP не изменяются.

Порядок: `pz stop --yes`, `pz save story_test --yes`, затем команда часов
с `--yes`, затем `pz start story_test`. Все операции используют общий lock pz.
Требуются активный story_test, clean exit 0, точный pinned Docker image,
свежая SHA/tar-проверенная cold backup после последней остановки, совпадающая
с текущим map_t.bin. Другие миры не поддерживаются. Никакого восстановления.

Формат проверен по GameTime.save/load(DataOutputStream/DataInputStream)
Build 42.21.0: GMTM, big-endian version249; float lastTimeOfDay по offset20,
float timeOfDay по offset24; day/month/year по offset28/32/36. Day и month
нулевые. Изменяются только восемь байтов offset20..27; вся дата, nightsSurvived,
множитель, популяция, Lua modData, погода и остальной хвост сохраняются байтово.
Оба значения часов синхронизируются, чтобы не переносить старую временную дельту.
Неизвестный формат, некорректная дата/часы, ссылки, другой образ и работающая
игра запрещают запись. После записи выполняются fsync и побайтовая проверка.

Фактическая загрузка и сохранение игрой проверяются отдельно от unit tests.
При изменении ABI требуется новый аудит, а не расширение allowlist вслепую.
Игровые события/погода и таймеры могут не соответствовать естественному
проживанию этого времени: команда намеренно меняет только часы.

После запуска: `pz save-live`, затем `pz story clock story_test --show` читает
сохранённые часы. Это проверка persisted save, не прямой снимок JVM.
