# Проверка двух клиентов: Гливице и Львов

Целевой сервер: `62.171.140.149:16261`, Build 42.21.0 со Steam.
Общий Server Password оставить пустым. Каждый использует собственные имя
персонажа/аккаунта и личный пароль; admin-пароль другим игрокам не передавать.
PUBLIC=false скрывает листинг, но не заменяет ограничение входа по IP/учётным записям.

Выполнено с локального Ubuntu: A2S info-ответ UDP/16261 и RakNet pong UDP/16262
после штатного рестарта vanilla. Это проверяет протоколы/маршрут, но не вход
игрового клиента, синхронизацию персонажей и транспорт. Внешний IPv6 ещё не
проверен: на локальной машине нет маршрута IPv6. Правила IPv6 на VPS включены.

## Сценарий, 20–30 минут

1. Сверить Build клиента и digest/mod snapshot сервера. У обоих игроков должны
   совпадать активные Mod IDs и актуальные версии Workshop. Сначала выполнить
   vanilla baseline; для модов повторить тот же маршрут после согласованного
   переключения и холодного backup. Не подключаться во время bootstrap-рестарта.
2. Игрок из Гливице подключается напрямую по IP, затем игрок из Львова.
   Проверить журнал: 2 соединения, нет Steam relay fallback/ошибок Workshop,
   загрузка персонажей и одинаковое состояние двери, контейнера и предметов.
3. На одной vanilla-машине проехать город -> трасса -> город; поменяться
   водитель/пассажир, проверить торможение, повороты, выход/вход в машину,
   движение головой и анимации Immersive Driving с обеих сторон. Повторить
   отдельно с Viewpoint и без него. Проверить отсутствие телепортации машины,
   зависшего пассажира, отката предметов и несогласованных столкновений.
4. Для TLOU проверить одинаковые типы infected у обоих игроков, урон и здоровье,
   сохранение типа после выхода/входа и повторного захода в область. Проверить
   Clicker/Bloater: известные MP-особенности нельзя считать проверенными по
   одному headless-старту. Bandits/Creator исключены, их NPC не должны появляться.
5. Записать клиентские FPS отдельно для каждого ПК (камера/графика влияют на
   них), RTT/loss и серверные FPS/tick/statistics при двух игроках. CPU/RAM/steal
   сервера снимать одновременно через root-monitor; docker CPU% не является TPS.
   Сохранить времена/симптомы и отфильтрованные фрагменты ошибок.
6. Оба игрока выходят. Проверить players=0 через внутренний RCON, сохранить мир,
   согласовать штатный рестарт. Подключиться повторно и проверить персонажей,
   машину, содержимое багажника и состояние infected.

Критерий приёмки: оба игрока действительно подключились без общего пароля,
игровые состояния совпадают, нет нарастающих Lua/Java ошибок, OOM или рестартов,
мир и персонажи пережили save/restart. Только после этого отмечать модпак как
проверенный в мультиплеере. Клиентские camera addons не добавлять в server JVM.

## Клиентский ZombieBuddy

Вручную выполнить инструкции автора для своей ОС. Linux/macOS: ZombieBuddy.jar
и Java agent; Windows: инструкция с zbNative.dll. Не переносить Windows DLL на
VPS. Не использовать allow-all: подтверждать конкретные проверенные JAR/hashes.
Living Props явно client-only; Barricade Fix/Bodycam/Death Cam — графические
клиентские дополнения, не включённые в dedicated-набор. Death Cam Workshop
3816588758 подтверждён, но автор не подтвердил собственный MP-тест.
