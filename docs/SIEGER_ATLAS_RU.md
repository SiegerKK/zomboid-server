# Универсальный атлас зданий и анализ заражённых — SiegerAdmin

**Статус:** Draft, исходники и моки Build 42; на игровой сервер не установлено.
Разработка ведётся поверх PR #29. Код не привязан к Rosewood или конкретному пресету.

## Зачем

Цель — объективная калибровка локаций по мотивам The Last of Us:
геометрия зданий + наблюдаемые загруженные инфицированные + потенциальные
концентрации в кварталах. Это **не** оценка числа всех зомби, записанных на
диске, и не симуляция новых зомби.

## 1. Сервер: метаданные зданий произвольной области

```bash
# Любой активный Story-enabled мир с установленным SiegerAdmin:
sudo pz story atlas capture story_test \
  --bbox 7980,11480,8460,11800 --floors 0:3
# По умолчанию PREVIEW. Только явный запрос запускает скан:
sudo pz story atlas capture story_test \
  --bbox 7980,11480,8460,11800 --floors 0:3 --yes
sudo pz story atlas status story_test # progress running / complete
# Для длительного обхода: sudo pz story atlas stop story_test --yes
sudo pz story atlas export story_test \
  --output /var/tmp/rosewood-atlas.json \
  --geojson /var/tmp/rosewood-buildings.geojson
```

Rosewood **только пример**; координаты передаются параметрами.
`--bbox x0,y0,x1,y1` использует включённые нижние и **исключённые**
верхние границы. Диапазон этажей `--floors MIN:MAX` включительный.

Из `getWorld():getMetaGrid():getBuildings()` собираются:
полные границы `BuildingDef` каждого здания, набор помещений
`RoomDef` и **каждый прямоугольник** `getRects()` на выбранных этажах.
Один источник метаданных обрабатывается за **один запрос**; нет
подгрузки чанков, предметов, патрулей, AI hooks или обычных таймерных
сканирований. Работает с любым городом/модовой картой, которая внесена
в игровой MetaGrid. Метаданные **не включают** самодельные постройки
игроков и не дают точные формы дорожек, проходимости, дверей и заборов.

Исходный building `bbox` — только **ограничивающий прямоугольник**,
его нельзя считать площадью интерьера. Точную площадь мы рассчитываем
как объединение прямоугольников комнат отдельно по этажам.
Геометрия здания в GeoJSON помечена `building_bbox`, комнаты —
`room_rect`; система координат — **клетки PZ, НЕ WGS84**.

Загруженные чанки считываются **из серверной ветки**
`IsoCell:getChunkForGridSquare(x,y,0)` через `ServerMap` на сетке
**8×8 клеток**. Ранее использовавшийся `getChunk(wx,wy)` опирался
на клиентскую `IsoChunkMap` и в реальном dedicated JVM давал
ложное нулевое покрытие. Новый формат Atlas **v2** намеренно отклоняет
v1-экспорты с неправильной 10-клеточной сеткой. Ни один вызов
не создаёт чанк; присутствие чанка не доказывает проходимость,
полную загрузку всех этажей и отсутствие заражённых.
При недоступном методе покрытие — `unknown`.

Метаданные и чанки считываются **порциями по 256 шагов за тик**
(`OnTickEvenPaused`, coroutine), без ограничения общего количества.
`atlas status` показывает промежуточный `running` и счётчики,
`atlas stop WORLD --yes` останавливает только исследование.
Неполный файл никогда не считается законченным. Экспорт включает
время начала/окончания всей работы и отдельное окно времени
наблюдения за чанками. Большая область может обрабатываться
в течение многих кадров и требует отдельного замера нагрузки.

Приватный запрос/ответ: `SiegerAdminAtlasRequest.txt`,
`SiegerAdminAtlasResult.txt`, результат каждого запроса
`SiegerAdminAtlas-<request-id>.txt` внутри `world/data/Lua`.
Хранится read-only для игры, имеет одноразовый ID, проверку мира,
срок годности и защиту от повторного запуска. `status=complete`
устанавливается только после записи сверяемого footer. Сбой,
повреждение, несовпадение числа строк или переполнение бюджета
`--max-rows` — отказ, а не тихий пропуск зданий.
Данные экспортируются только в **новый** локальный файл вне Git,
с правами 0600, без изменения сохранения/содержимого карты.

## 2. Снимок инфицированных

На `story_test` в PR #29 уже есть режимы:

```bash
sudo pz story zombies snapshot story_test --yes
sudo pz story zombies status story_test
sudo pz story zombies report story_test \
  --output /var/tmp/zombie-snapshot.json
```

`zombies report` сохраняет полный приватный набор JSON-строк.
Его **не** следует заменять `zombies analyze` при пространственном
анализе: агрегированные производные события не являются
одной выборкой зомби. Для длинных записей поддерживается
`--sample first|last|N`: один полный кадр, а не сумма кадров.

Альтернативно можно использовать уже существующий `tlou roster`:
```bash
sudo pz story tlou roster story_test --player admin --yes
sudo pz story tlou result story_test --output /var/tmp/roster.json
```
Формат старого roster **не содержит идентификатор мира**, поэтому
его источник нужно указать вручную через `--source-world`;
оператор несёт ответственность за совпадение мира и сохранения.
При несовпадении контекста, неполном кадре или неверных счётчиках
анализатор откажется работать.

## 3. Построение плотности и heatmap

```bash
# С полным Debug-трейсом:
sudo pz story atlas analyze \
  --atlas /var/tmp/rosewood-atlas.json \
  --trace /var/tmp/zombie-snapshot.json \
  --sample last --grid-size 25 \
  --output /var/tmp/rosewood-density.json \
  --geojson /var/tmp/rosewood-density.geojson

# Либо с TLOU roster:
sudo pz story atlas analyze \
  --atlas /var/tmp/rosewood-atlas.json \
  --roster /var/tmp/roster.json \
  --source-world story_test --grid-size 25 \
  --output /var/tmp/rosewood-density.json
```

Анализатор выполняется **полностью офлайн**, не читает игровой мир,
не создаёт и не удаляет зомби. Выводит:

- наблюдаемых заражённых в выбранной области и по типу;
- количество по сетке произвольного размера (обычно 10/25/50 клеток);
- попадания в реальные прямоугольники комнат **с учётом этажа**;
- сколько уникальных зданий занято *наблюдаемыми* зомби;
- площадь метаданных комнат по этажам с точным устранением перекрытий;
- оценки числа заражённых на 1000 горизонтальных клеток сетки и,
  отдельно, на 1000 клеток **присутствующих чанков**.

**Нельзя** считать последнюю оценку плотностью всех сохранённых
зомби: сервер сообщает лишь объекты в загруженном списке.
Для нормирования по площади загруженных чанков анализатор дополнительно
сопоставляет точные wall-clock timestamps Atlas и одного кадра ZombieDebug.
По умолчанию разрешает эту производную плотность только при интервале
сканирования покрытия не длиннее 2 секунд и расхождении снимков не более
2 секунд. В иных случаях значение плотности по загруженным чанкам — `null`,
а причина отражена как `unsynchronized_or_unknown_time`.
Для TLOU roster без исходного времени снимка эта плотность тоже не
выдаётся автоматически. Оператор может явно выбрать
`--allow-stale-coverage`, получив маркировку
`operator_override_stale_unverified`; это **не** делает данные
синхронными. Длительные сканы города нельзя интерпретировать как
мгновенный снимок его текущей загрузки.
Пустая клетка тепловой карты **не означает** доказанную безопасность.
`per_1000_loaded_chunk_tiles_estimate=null` для недоступного
покрытия; разность между `building_bbox` и `room_rect` не
смешивается, пересекающиеся комнаты не умножают число врагов.
Многоэтажность также явно сохраняется в статистике построек.

## 4. Эксперимент по Bill's Town

Исследовать несколько сравнительных областей по одному протоколу:
тихий residential, дорога между укрытиями, школа/церковь, опасный квартал.
Для каждой области нужны одинаковые настройки мира, характер
движения игрока, одинаковые часы и одна полная выборка зомби.
Поиск щелкунов в помещениях и среднее число контактов с ними —
лучший следующий вопрос, чем просто население всего Rosewood.
Для измерения погонь и переходов AI используйте существующий
`pz story zombies record` из PR #29, не дублируя profiler.

## Приёмка

Моки Python/Lua 5.1 тестируют любой активный Story-мир,
пересечение областей, комнаты с перекрытиями, два этажа,
полное покрытие, порядок и идентичность кадров, отказ при
незавершённом или искажённом результате. **Точный B42.21**
API `MetaGrid.getBuildings()` и `RoomDef.getRects()` нужно
проверить на запущенном выделенном сервере до доверия цифрам.
PR не деплоен, сохранения и живой мир не менялись.


## Телепортация для тестовых маршрутов

Для переноса точного **онлайн**-игрока в другой район пользуйтесь
штатным движковым сетевым `teleportto` через root-only RCON `pz`:

```bash
sudo pz story teleport story_test admin 8341 11612 0       # только preview
sudo pz story teleport story_test admin 8341 11612 0 --yes
sudo pz story ops players story_test --yes               # подтвердить прибытие
```

Команда работает с **любым активным миром**, даже без SiegerAdmin. Это
не координаты глобальной карты/широта-долгота, а точные world X/Y/Z. При
неверном логине, другом активном мире или некорректных координатах отправка
не производится. Используется серверная команда, не непосредственный
`setX/setY/setZ`, поэтому перенос в ещё не загруженный район обрабатывает
сам игровой сервер. Серверный ответ не доказывает, что клиент уже загрузил
место назначения. Выбирайте заведомо доступную плитку и проверяйте у игрока.
