# SiegerRadio — музыкальная станция, радиомебель, автомобильные приёмники

**Статус:** PR #23, код и offline-тесты; совместимость в настоящем Build
42.21.0 dedicated MP ещё должна пройти двухклиентную приёмку. Только
`story_test`, `road_home` не трогать. Установка или merge исходников
**не приводит** к автоматическому запуску радиостанции.

## Цель

Станция **NORTHBOUND FM 101.2 МГц** воспроизводит заранее установленные
музыкальные записи **по одной, в случайном порядке**. Музыка начинается
сразу после предыдущего трека, без расписания, без обязательного диктора
и без онлайн-потока с VPS.

Сервер хранит общую перемешанную очередь. Каждый зарегистрированный
трек появляется **один раз за цикл**, новый цикл перемешивается снова
и не начинается той же песней, на которой закончился предыдущий.
Клиентам передаётся `clip ID`, но не байты MP3/WAV. Устройства
взаимодействуют с местной радиоволной только при наличии питания,
включённом состоянии, ненулевой громкости и частоте 101200 кГц.

Звук позиционный: около включённого `IsoRadio` на столе или
автомобиля возникает локальный аудиоисточник. Радио в руках/верхнем
инвентаре продолжает воспроизводить звук в личном канале, как раньше.
При отключении питания, смене волны или выходе за пределы зоны (12
клеток) звук должен прекращаться. Отделённый двухклиентный тест
обязателен, особенно для FMOD 3D emitter и сетевого состояния авто.

**Режим PR #24 — потоковое воспроизведение по требованию:** клиент хранит только ID композиции, длительность и время окончания. Только когда рядом есть включённый приёмник на 101.2 МГц, одобренный клиентский Java-мост ZombieBuddy открывает один потоковый FMOD-файл из локального проверенного пакета, устанавливает позицию в миллисекундах и включает звук. Если игрок ушёл, выключил радио, отключил питание или сменил частоту — мост останавливает канал и освобождает ресурсы. Возвращение открывает поток с новой позицией эфира; это также относится к новому игроку посреди песни. В старом коде беззвучный поток работал постоянно и расходовал ресурсы впустую; он удалён.

**Статус:** обвязка и отдельные Lua/Java-моки готовы, но точные native FMOD-параметры Build 42.21.0 и слышимость обязаны пройти клиентский приёмочный тест. На несовместимой игре Java-мост откажется играть; автоматической замены на CPU-затратный беззвучный поток нет. Клиентам требуется пакет `sr17-v1-023e01823321`, отдельно построенный Java JAR и подтверждение прав загрузки в ZombieBuddy. Передача музыки по сети не выполняется.


## Радио Томаса после согласованного отката мира

`smokeys_bar_03_upstairs` больше **не содержит `loot Base.HamRadio1`**.
Вместо него одно действие `radio_furniture` размещает настоящий
`IsoRadio` в `(10621,9232,1)` на уже обследованном кухонном столе
`furniture_tables_high_01_15`, объект #2, высота по реальному скану 32/96 ≈ 0.333 (PR #22).
Лист `RADIO WATCH` остаётся рядом.

Операция не конвертирует, не удаляет и не перемещает ни одного
ранее существовавшего предмета. Проверяются прежний table selector,
класс/спрайт, фактическая высота, отсутствие другого `IsoRadio`,
отсутствие прежнего токена переносной радиостанции, шаблон
`Base.HamRadio1`, наличие подходящего ванильного world sprite и
возможность установить `DeviceData`. Если на конкретной B42.21.0
не существует ожидаемого спрайта/метода, операция **отказывает без
появления мебели** и требует доработки по реальному игровому журналу.

Функция `ISMoveableSpriteProps:getTotalTableHeight(square)` нужна для
отступа от столешницы. Фактический 3D-вид и возможность использования
из контекстного меню нужно проверить на клиенте после *одного*
установленного экземпляра. Радио создаётся выключенным; игроки
включают его и обеспечивают заряд/электричество штатным способом.

Разрешение для одной сцены:

```bash
sudo pz story apply-live story_test smokeys_bar_03_upstairs \
    --allow-radio-furniture --yes
```

Не применять, если действие или вся сцена уже внесены в ledger
живого мира. По откату, о котором сообщил владелец, перед повторным
прохождением необходимо **сверить актуальный save и Story-флаги**.
Механический reset/bypass scene ID без аудита запрещён.

## Подключение музыкального архива

Архив владельца получен: зарегистрирован 41 трек, без обрезки.
Инструкция и ограничения доставки: `docs/STORY_RADIO_OWNER_TRACKLIST_RU.md`.
Бинарный клиентский ZIP распространяется отдельно от Git; всем игрокам
нужна его одинаковая версия. До её установки станцию не включать.

`scripts/radio_assets.py` расширен:

- Музыкальный вход → stereo PCM WAV, 16-bit, 22 050 Hz (FFmpeg); короткие CUE — mono;
- продолжительность каждого трека от 5 до 720 секунд;
- максимум 64 уникальных звуковых клипа, каждый не более 32 MiB;
- `--music` добавляет зарегистрированный клип в перемешиваемый плейлист;
- все PCM-байты сверяются с SHA-256; серверная/клиентская версии каталога
  меняются вместе; старые клиенты не получают новый звук без обновления мода.

Пример **после передачи треков**:

```bash
python3 scripts/radio_assets.py add --clip north_song_01 \
  --source /var/tmp/my_song_01.mp3 \
  --purpose "Песня ночного вещания NORTHBOUND" --music --yes

python3 scripts/radio_assets.py add --clip north_song_02 \
  --source /var/tmp/my_song_02.ogg \
  --purpose "Второй трек радиостанции NORTHBOUND" --music --yes

python3 scripts/radio_assets.py check
```

После обновления файлов нужен новый одинаковый клиентский мод на всех
подключённых клиентах и согласованное обновление серверных read-only
модулей. Мод автоматически из обычного Git checkout в клиентский PZ
**не передаётся**; для удобства позже опубликовать в Workshop.

Управление после установки:

```bash
sudo pz story radio station status story_test
sudo pz story radio station start story_test             # preview
sudo pz story radio station start story_test --yes       # реальный старт
sudo pz story radio station stop story_test --yes        # остановка
```

Станция запускается только с явной командой и достаточным плейлистом;
она не меняет обычный текстовый радиоэфир и не требует сторонних модов.

## План реального приёмочного теста

1. Убедиться, что мир именно `story_test`; никто не подключён.
   Создать согласованный cold checkpoint и не менять `road_home`.
2. Установить одинаковую версию SiegerRadio на обоих клиентах.
   Проверить HELLO/HELLO_ACK и `radio_assets.py check`.
3. На откатанном мире проверить точные стол и отсутствие старой
   переносной рации; применить `radio_furniture` **один раз**;
   убедиться, что появился настоящий кликабельный `IsoRadio` на столе
   (не `IsoWorldInventoryObject` на полу).
4. Включить стационарное радио и обеспечить питание, настроить 101.2;
   игроку рядом проверить 3D-звук. На другой частоте/без питания —
   музыка должна останавливаться.
5. В машине отдельно проверить `VehiclePart:getDeviceData()`,
   `VehiclePart:hasDevicePower()`, текущее положение и смену частоты.
   Два клиента слушают **один и тот же** трек в одном эфирном цикле;
   издалека музыка не слышна.
6. Провести перезапуск `story_test` с подтверждением двух клиентов:
   установленная фурнитура сохранена, дубликатов нет, очередной трек
   меняется без повтора и станция не включается сама, если была остановлена.
7. Если какой-либо JVM/FMOD метод не сработал — зафиксировать в приватном
   клиентском `console.txt` и серверных логах, не делать повторную
   мутирующую операцию вслепую.

Контекст: `docs/STORY_RADIO_TOOLKIT_RU.md` (исходный инструмент), ссылка
на PR #23 в репозитории. Git merge передаёт только исходники: ни установка радиомебели, ни перезапуск
на действующем VPS не выполняются автоматически.

## Подтверждённая проблема задней полусферы (Viewpoint)

В автомобиле при повороте головы музыка почти исчезает сзади
и резко уходит в один канал. Ближайший 3D radius=4 помогает
дистанции, но не исправляет саму чрезмерную моно-панораму.
В PR #24 подготовлены optional Stereo 3D Spread и безопасная
подготовка stereo из **оригинального** ZIP; все 41 независимых stereo-трека уже восстановлены и нормализованы, а Spread60 применяется только в салоне; дальнейшая игровая приёмка обязательна.
См. `docs/STORY_RADIO_3D_SPREAD_CONTINGENCY_RU.md`.
